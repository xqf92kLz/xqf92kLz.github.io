    5. 算术逻辑单位¶

    • ALU：Arithmetic & Logic Unit（算术逻辑单元）

      包含两个子单元：算术单元（处理数字运算）和逻辑单元（处理逻辑操作）。

    • 算术单元（Arithmetic Unit）

      • 加法器

        • 半加器（Half Adder）：

          功能：处理两个 1 位二进制数相加，输出 “和” 与 “进位”。

          实现：用 XOR 门 计算和，用 AND 门 计算进位。

        • 全加器（Full Adder）

          功能：处理三个 1 位二进制数相加（两个操作数 + 一个来自低位的进位）。

          实现：由两个半加器 + 一个 OR 门构成。

        • 8 位行波进位加法器

          功能：将两个 8 位二进制数相加。

          实现：用 1 个半加器处理最低位，再用 7 个全加器依次处理更高位，进位会 “逐位传递”。

      • 溢出（Overflow）

        运算结果超出了当前位数的存储范围。

        增加全加器数量，支持 16 位、32 位或更大位数的运算，，减少 / 避免溢出。

      • 其他运算

        • 基础运算：减法（带借位）、增量（+1）、减量（-1）、取反、移位等。

        • 乘除法：简单 ALU 没有专用电路，通过多次加减法实现；高级 ALU（如手机 / 电脑）有专门的乘法电路，速度更快。

    • 逻辑单元（Logic Unit）

      执行逻辑操作（如 NOT、AND、OR）和简单的数值测试。

      如，判断 ALU 输出是否为 0：用一堆 OR 门检查检查有没有 1，再用 NOT 门取反，只有全 0 时输出 1。

    • ALU 的抽象与接口

      • 抽象的意义：工程师将 ALU 封装为独立组件，无需关心底层逻辑门细节，只需关注输入输出，大大简化了设计工作。

      • 标准接口：

        • 输入：两个 8 位操作数 A、B 及 4 位操作码（如 1000 代表加法，1100 代表减法）。

        • 输出：8 位运算结果及 Flag 标志位（Overflow Flag：判断是否溢出；Zero Flag：判断结果是否为 0；Negative Flag：判断结果是否小于 0）

    • 英特尔 74181：1970 年发布，是首个封装在单芯片内的完整 ALU，仅支持 4 位运算，约 70 个逻辑门，无乘除功能。

    6. 寄存器 & 内存¶

    • 锁存器（Latch）

      • 定义：利用 AND、OR、NOT 等基础逻辑门搭建的电路，核心功能是在通电状态下存储 1 位二进制数字（0 或 1）
      • 保持原理：通过反馈回路（将输出连回输入）实现状态保持，电路会“记住”上一次的输出并自我强化
      • 典型结构：AND-OR 锁存器
        • 输入：Set（置 1）、Reset（置 0）
        • 输出：Q（存储的 1 位数据）
        • 工作过程
          • 置 1（Set=1，Reset=0）：Set 触发 OR 门输出 1，该值通过反馈回路使 AND 门输入保持 1，即使 Set 变回 0，电路仍输出 1
          • 置 0（Reset=1，Set=0）：Reset 触发 AND 门输出 0，该值通过反馈回路使 OR 门输入保持 0，即使 Reset 变回 0，电路仍输出 0
          • 保持（Set=0，Reset=0）：无新触发信号，电路停留在上一次输出状态，反馈回路持续强化当前值
      • 操作定义：写入（向锁存器存入数据）、读取（从锁存器取出数据）

    • 门锁（Gated Latch）

      • 改进背景：原始锁存器需两条独立输入线（Set/Reset）控制状态，使用不便，因此增加逻辑门优化为“门锁”
      • 核心设计
        • 数据输入线（D）：控制要存储的数值（0 或 1）
        • 允许写入线（WE）：控制是否允许更新存储内容，像一道“门”
      • 工作流程
        • 写入（WE=1）：“门打开”，数据输入 D 的值传递到锁存器的 Set/Reset 端口，锁存器状态随 D 更新
        • 锁定（WE=0）：“门关闭”，数据输入 D 与锁存器隔离，反馈回路独立工作，锁存器保持上一次存储的数值，不受 D 变化影响
      • 名称由来：允许写入线（WE）控制“门”的开关，打开时允许写入，关闭时锁定状态

    • 寄存器（Register）

      • 组成：由一组并排排列的门锁（或锁存器）构成，解决单个锁存器仅能存储 1 位数据的局限
      • 核心概念：位宽
        • 定义：寄存器能存储的单个数字的二进制位数，代表一次可处理的数据量
        • 发展历程：8 位 → 16 位 → 32 位 → 64 位（现代主流计算机普遍使用 64 位寄存器）
      • 示例：64 位寄存器由 64 个并排的门锁组成，可一次性存储一个 64 位二进制数

    • 门锁矩阵（Latch Matrix）

      • 问题背景：寄存器位宽增大时，并排布局会导致所需线路数量急剧增加（如 64 位寄存器需至少 129 根线），电路设计复杂
      • 矩阵结构：将门锁以 n×n 网格形式排列，替代并排布局，n×n 矩阵可存放 n² 个门锁，大幅减少线路数量
      • 位址：每个门锁在矩阵中的位置由“行”和“列”唯一确定，行和列的编号组合即为“位址”；启用某个门锁需同时激活对应的行线和列线
      • 多路复用器：将输入的二进制地址转换为矩阵的行和列信号，实现对特定门锁的精准选择
      • 优势：256 位存储仅需 35 根线（1 根数据线、1 根允许写入线、1 根允许读取线、16 根行线、16 根列线），相比并排布局的 513 根线，线路数量大幅减少

    • 内存（Memory）

      • 组成逻辑：多个门锁矩阵及辅助电路封装为“内存方块”（如 256 位存储模块），再将多个内存方块并排排列，形成可寻址的统一内存单元
      • 随机存取存储器（RAM）：由一系列嵌套的门锁矩阵及控制电路组成，核心特点是可根据地址随机访问任意存储位置，读写速度不受存储位置影响
      • 规模扩展：现代计算机内存容量从 MB（兆字节）发展到 GB（千兆字节）甚至 TB（太字节），核心方式是不断嵌套和组合小存储单元，通过增加地址位数（如 32 位地址可寻址 4GB 内存，64 位地址支持更大容量）实现容量提升
      • 类比：RAM 类似人类短期工作记忆，用于临时存储当前处理的数据和程序状态，断电后数据丢失；持久存储（如硬盘、SSD）类似长期记忆，断电后数据仍可保留

    7. 中央处理器（CPU）¶

    • CPU 的概念

      • 即中央处理单元，负责执行程序，通常由寄存器 + 控制单元 + ALU + 时钟组成，与 RAM 配合，执行计算机程序
      • CPU 和 RAM 之间用“地址线”、“数据线”和“允许读/写线”进行通信

    • 重要组件

      • 指令表：为 CPU 支持的每一种指令分配唯一的 ID，形成的对照表，是 CPU 解码指令的依据。包含指令、描述、4 位操作码、指令的操作对象（地址或寄存器）

        示例

        指令：LOAD A；描述：Read RAM location into register A；操作码：0010；操作对象：4-bit RAM address

        指令：ADD；描述：Add two registers, store result into second register；操作码：1000；操作对象：2-bit register ID，2-bit register ID

      • 寄存器组

        • 通用寄存器：用于临时存储和操作数据，运算过程中需用到的数据、运算结果都会暂时存放在这里
        • 专用指令寄存器：仅用于处理指令相关操作，不存储普通数据
          • 指令地址寄存器（Instruction Address Register）：追踪程序运行到哪里了，即存储当前指令的内存地址。开机初始化时值为 0，每执行完一条指令，自身会自增 1，工作时会将存储的地址发送给 RAM，让 RAM 返回对应地址的指令交给指令寄存器
          • 指令寄存器（Instruction Register）：用于存储当前指令。指令的前 4 位为操作码，后 4 位为数据来源（寄存器或内存地址）

      • 控制单元

        • 组成：与 ALU、锁存器等组件一样，本质是由大量逻辑门组成的组合逻辑电路
        • 核心功能（类似管弦乐队的指挥）：
          1. 解码指令：接收指令寄存器中的指令，解析前 4 位操作码，匹配指令表，确定指令类型和操作对象（寄存器 / RAM 地址）；比如检测到操作码 0010，就识别为 LOAD A 指令
          2. 配置组件：根据解码结果，控制 CPU 内部各组件协同工作 —— 执行内存指令时，控制 RAM 的读 / 写线、地址线和数据线，控制寄存器的写使能；执行数学指令时，选择对应的寄存器作为 ALU 的输入，配置 ALU 执行具体运算（如加法）
          3. 同步协调：接收时钟的电信号，确保 “取指令→解码→执行” 三个阶段按节奏同步进行，避免组件操作混乱

    • 指令执行过程

      • 取指令阶段（Fetch Phase）

        • 指令地址寄存器将当前指令的内存地址发送给 RAM
        • RAM 返回该地址存储的指令，复制到指令寄存器中

      • 解码阶段（Decode Phase）

        • 控制单元读取指令寄存器中的 8 位指令，将其拆分为前 4 位（操作码）和后 4 位（操作数）
        • 控制单元通过逻辑电路检测操作码，匹配指令表，确定指令类型和具体操作
        • 解析操作数，确定操作对象（是 RAM 地址，还是寄存器编号）

      • 执行阶段

        • 控制单元根据指令类型配置 CPU 组件：

          • 内存指令：

            • LOAD A：控制单元向 RAM 发送操作数（RAM 地址），打开 RAM 的 “允许读取线”，打开寄存器 A的 “允许写入线”，将 RAM 对应地址的值传递到寄存器 A
            • STORE B：控制单元向 RAM 发送操作数（RAM 地址），打开 RAM 的 “允许写入线”，打开寄存器 B 的 “允许读取线”，将寄存器 B 中存储的值传递到 RAM 对应地址

          • 数学指令（ADD 等）：控制单元选择正确的寄存器作为 ALU 的输入，配置 ALU 执行正确的操作，控制单元用自己的寄存器将结果暂存，关闭 ALU 后再将结果写入目标寄存器

        • 指令执行完成后，指令地址寄存器自增 1，准备取下一条指令

      示例

      取指令阶段：指令地址寄存器值为 0→RAM 地址 0→返回指令 00101110→复制到指令寄存器

      解码阶段：指令 00101110，操作码 0010→识别为 LOAD A 指令；操作数 1110（十进制 14）→确定操作对象是 RAM 地址 14

      执行阶段：控制单元向 RAM 发送操作数（RAM 地址 14），并打开 RAM 的 “允许读取线”；RAM 根据地址 14，返回该地址存储的值（00000011，十进制 3）；控制单元打开寄存器 A 的 “允许写入线”，将 RAM 返回的值传递到寄存器 A

    • 时钟

      • 作用：负责管理 CPU 运行的节奏，以精确的间隔触发电信号，控制单元用这个信号来推动 CPU 的内部操作，确保各组件同步执行
      • 时钟速度：CPU 完成“取指令→解码→执行” 循环的速度，单位是赫兹（Hz），是衡量 CPU 性能的重要指标，单位是赫兹（Hz），1Hz=1 次 / 秒
      • 超频：修改时钟速度，加快 CPU 的速度，超频过多会让 CPU 过热或产生乱码，因为信号传输跟不上时钟节奏
      • 降频：降低时钟速度，达到省电的效果，这对笔记本/手机等电池供电设备很重要
      • 动态调整频率：按需求加快或减慢时钟速度，根据负载自动调节性能与功耗

    8. 指令和程序¶

    • 指令集
      • 定义：CPU 支持的所有指令的集合，为每条指令分配唯一的 4 位操作码（opcode），指令总长度为 8 位，后 4 位用于指定操作对象（RAM 地址或寄存器编号），形成统一的指令对照表，供控制单元解码使用
      • 指令的二进制结构：每条指令固定 8 位，前 4 位 = 操作码（标识指令类型），后 4 位 = 操作数（标识操作对象），例如 “LOAD_A 14” 对应二进制 “0010 1110”，0010 = 操作码（LOAD_A），1110 = 操作数（RAM 地址 14）
      • 指令分类
        • LOAD 指令：例如 LOAD_A，通过数据线将 RAM 中指定地址的数据传至寄存器 A
        • STORE 指令：例如 STORE_B，把寄存器 B 的值存入特定 RAM 地址
        • ADD 指令：例如 ADD B A，告诉 ALU 把寄存器 B 和 A 中的数字相加，结果存到 A 中
        • SUB 指令：例如 SUB B A，告诉 ALU 把寄存器 B 和 A 中的数字相减，结果存到 A 中
        • JUMP 指令：程序跳转至对应的 RAM 地址读取指令（实现：控制单元解码操作码后，将指令后 4 位对应的 RAM 地址，直接写入 “指令地址寄存器”），无条件跳转；也可条件跳转，如 JUMP_NEGATIVE 的跳转条件是 ALU 的负数标志为 True
        • HALT 指令：程序运行结束，避免 CPU 处理无效数据导致崩溃
    • 扩展指令长度
      • 背景：早期计算机每个字 8 位，指令仅占 4 位，最多支持 16 个指令，且 4 位地址仅能寻址 16 个 RAM 位置，无法满足需求
      • 策略一：固定长指令，使用更多位表示指令（如 32 位或 64 位），增加操作码和地址的编码空间
      • 策略二：可变指令长度，不同指令长度不同，节约位数，如 HALT 指令无需额外值，可直接执行。设计使 CPU 取指令阶段更复杂，但提升了灵活性

    9. 高级 CPU 设计¶

    • 早期提升 CPU 性能的方法

      • 早期：通过减少晶体管的切换时间来提升速度，但很快达到极限
      • 后来：给 CPU 设计专门的硬件电路，实现复杂操作，避免软件循环的低效
        • 例如：专门的除法电路，替代多次减法实现除法，减少时钟周期消耗
        • 指令集扩展：如 MMX、3DNow!、SSE等，增加专用电路处理图形操作、视频解码、加密等任务，这些操作用标准指令需要大量时钟周期
        • 指令集发展：为了向后兼容，旧指令会被保留，导致指令集不断扩大，从早期英特尔 4004 的 46 条指令，发展到现代处理器的上千条指令及变种

    • 缓存（Cache）

      • 定义：在 CPU 内部设置的小块内存，解决 RAM 与 CPU 之间的数据传输延迟问题

      • 核心目的：防止 CPU 空等数据，因为 RAM 是独立于 CPU 之外的内存模块，数据必须通过总线在 CPU 和 RAM 之间传输，而数据通过总线传输存在延迟（即使总线很短、电信号接近光速，在 GHz 级别的 CPU 运行速度下，微小的传输延迟也会让 CPU 长时间空等），且 RAM 本身寻址、取数也需要时间

      • 工作机制

        • CPU 请求数据时，RAM 不只是返回单个值，而是传输一批连续的数据块到缓存（缓存利用数据局部性原理提升效率，即程序和数据大多是连续存储和顺序处理的）

          1. 如果 CPU 后续需要的数据已经在缓存中，称为缓存命中，可在一个时钟周期内获取数据，无需访问 RAM

          2. 如果需要的数据不在缓存中，称为缓存未命中，必须重新从 RAM 读取，产生延迟

      • 脏位（Dirty Bit）

        • 定义：缓存中用于标记数据块与 RAM 中数据不一致的标志位
        • 产生场景：缓存也可作为临时存储空间，存放复杂运算的中间结果，避免频繁读写 RAM。当 CPU 将数据写入缓存而非直接写回 RAM 时，缓存中的数据与 RAM 中的数据不一致，为标记这种状态，缓存为每个数据块设置一个特殊标志位，称为脏位
        • 缓存同步：当缓存存满且需要加载新的数据块时，会先检查脏位，如果数据块被标记为脏，说明与 RAM 不一致，必须先将该数据写回 RAM，再清空空间加载新数据，保证数据最终一致

    • 指令流水线（Instruction Pipelining）

      • 核心目的：让取指令、解码、执行三个指令执行阶段并行进行，提升 CPU 吞吐量
      • 工作原理
        • 传统方式：按顺序执行“取指令→解码→执行”，每个指令需要 3 个时钟周期，CPU 各部分存在闲置
        • 流水线方式：在执行当前指令时，同时解码下一条指令、取址下下条指令，使 CPU 各部分同时工作，理想情况下每个时钟周期可完成一个指令，吞吐量提升至原来的 3 倍

      • 设计难点及解决方案

        • 数据依赖：后一条指令需要使用前一条指令的运算结果，此时若直接并行执行，会读取到旧的错误数据，导致运算结果出错

          高端处理器通过乱序执行解决该问题，动态重新排列有依赖关系的指令顺序，优先执行无依赖的指令，最小化流水线停顿时间

        • 条件跳转：跳转方向依赖前一条指令的运算结果，简单流水线处理器遇到跳转指令时必须停顿，等待结果确定后再继续填充流水线，造成明显延迟

          为解决该问题，高端 CPU 使用推测执行，提前猜测跳转方向，并将对应指令预先装入流水线。配合分支预测技术，通过复杂算法判断跳转方向，现代处理器的预测准确率超过 90%

          如果预测正确，流水线可无缝继续运行；如果预测错误，必须丢弃所有推测结果并清空流水线，称为流水线刷新，会产生一定性能损失

    • 超标量处理器（Superscalar Processor）

      • 背景：即使采用流水线设计，在指令执行阶段仍会出现部分 CPU 硬件闲置的情况。例如执行内存读取指令时，ALU 会完全空闲，造成硬件资源浪费

      • 超标量处理器一次性取指令和解码多条指令，同时执行需要不同 CPU 部件的指令

      更进一步，处理器会增加重复的硬件电路，例如配置 4 个、8 个甚至更多完全相同的 ALU

      这样可以在同一时刻并行执行多条数学运算指令，实现单个时钟周期内完成多条指令

    • 多核处理器

      • 定义：在单个 CPU 芯片中集成多个独立的处理单元（核心），可同时运行多个指令流
      • 优势：核心间整合紧密，可共享缓存等资源，便于合作完成复杂计算，比多个独立 CPU 更高效
    • 多 CPU 系统：当多核仍无法满足性能需求时，可在一台计算机中集成多个独立 CPU，常见于服务器等高性能场景
    • 超级计算机：由大量 CPU 和核心组成的高性能计算系统，用于超大规模计算任务（如宇宙形成模拟、气候预测等）

    10. 早期的编程方式¶

    • 穿孔纸卡
      • 原理：通过在纸卡上打孔来记录数据，用读卡器读取，连通电路，进行编程；穿孔纸卡的亲戚是穿孔纸带，原理类似但为连续形式
      • 历史应用：
        • 编程鼻祖：雅卡尔织布机（19 世纪初），纸卡上的孔控制织布机经线的升降，纬线穿过时形成图案，不同孔位组合对应不同花纹
        • 数据统计：1890 年美国人口普查，每张卡存一个人的信息，读卡器通过孔触发对应统计项 +1，但早期汇总机仅能执行固定的统计操作，纸卡存储的是 “数据” 而非 “程序”，机器本身不可编程
        • 程序存储：20 世纪中期至 80 年代的计算机，穿孔纸卡读取器将纸卡内容逐张写入内存，一叠纸卡可存储完整程序和数据。在纸卡叠侧面绘制斜线（striping），若不慎散落，可通过斜线快速恢复顺序。美国空军 SAGE 防空系统（1955 年）主控制程序存储在 62,500 张穿孔纸卡上，数据量约 5MB，项目巅峰期雇佣了全球约 20% 的程序员，是当时最复杂的软件项目之一
        • 输出功能：程序运行结果可通过打孔机写回纸卡，用于人工分析或作为其他程序的输入数据
        • 衍生形式：穿孔纸带。原理与纸卡一致，但为连续长条，可存储更长的指令序列，避免纸卡叠的散落问题
      • 缺点：早期用于汇总机时操作单一，不能编程；纸卡叠易弄散，整理耗时
    • 插线板（Plug Boards）
      • 原理：通过在面板插孔间插拔电缆，改变机器内部组件（如 ALU、寄存器、内存）的连接关系，实现不同的运算逻辑
      • 历史应用：
        • 早期机电计算机（20 世纪 20-40 年代），20 年代后出现可更换的插线板，无需每次重新布线，切换程序只需更换插线板。IBM 402 核算机（1940 年代）用于企业盈亏计算，插线板上的复杂连线对应加减乘除及条件判断逻辑。插线板上的电缆密集缠绕，编程难度极高
        • 电子计算机：ENIAC（1946 年），使用大量插线板和开关来配置程序，是世界上第一台通用电子计算机。但程序在纸上设计完成后，物理连线和调试可能需耗时三周
      • 缺点：操作复杂，连线非常耗时；早期计算机成本高，停机换程序的成本无法接受，急需更灵活的编程方式
    • 面板拨开关
      • 原理：通过拨动面板上的开关，输入二进制操作码，按存储键写入内存，再按运行键执行程序；面板上的指示灯显示函数状态和内存值
      • 历史应用：
        • 20 世纪 50-60 年代的计算机有大型控制台，虽少见但可通过开关输入完整程序
        • 早期家用计算机（如 Altair 8800）大量使用，因为家庭用户负担不起昂贵外设（如穿孔纸卡读取器）；Altair 8800 是第一款商业成功的家用计算机，1975 年发售，编程时需逐行拨动开关输入二进制指令
      • 缺点：编程繁琐，需要深入了解底层硬件（如操作码、寄存器），效率极低
    • 冯诺依曼计算机（存储程序计算机）
      • 核心思想：将程序和数据统一存储在共享内存中，而非以物理插线板形式存在，程序易于修改，CPU 可快速访问
      • 架构标志：一个处理器（包含算术逻辑单元 ALU）+ 数据寄存器 + 指令寄存器 + 指令地址寄存器 + 内存（负责存储数据和指令）
      • 历史发展：
        • 第一台冯诺依曼架构的“存储程序计算机”由曼彻斯特大学于 1948 年建造完成，绰号“Baby”
        • 现代计算机（包括当前使用的设备）仍采用冯诺依曼架构
      • 意义：解决了早期编程方式的低效问题，为后续编程语言的发展奠定了基础

    11. 编程语言发展史¶

    • 硬件编程的局限与软件的诞生
      • 早期编程需直接操作硬件（插线板、开关、穿孔纸卡），繁琐不灵活
      • 软件诞生目的：提供更通用的编程媒介，提升效率，降低硬件依赖
    • 机器语言（Machine Language / Machine Code）
      • 定义：计算机唯一能直接理解的语言，由纯二进制（0 和 1）指令组成
      • 结构：指令固定长度（如 8 位），前 4 位操作码、后 4 位操作数
      • 编程流程：纸上写伪代码→手动翻译为二进制→通过穿孔纸卡/纸带输入
      • 缺点：可读性差、易出错、修改难，完全依赖硬件，不同 CPU 不兼容
    • 汇编语言（Assembly Language）与汇编器（Assembler）
      • 诞生背景：机器语言效率极低，20 世纪 40-50 年代出现的中间语言
      • 核心改进：操作码用助记符（LOAD_A、ADD 等）表示，操作数无需二进制编码
      • 汇编器作用：读取汇编指令，自动转换为机器码，支持标签、自动计算跳转地址
      • 本质：与机器指令一一对应，仍依赖硬件，需手动管理寄存器和内存
      • 缺点：硬件绑定强，修改程序可能需大量调整代码
    • 高级编程语言的诞生与发展
      • Grace Hopper 与首个编译器
        • 背景：哈佛 Mark 1 首批程序员，经历原始编程的繁琐
        • 贡献：设计首个高级语言 A-0，1952 年开发首个编译器，实现高级语言转汇编/机器码
      • 早期高级语言
        • FORTRAN（1957 年，IBM 发布）：代码比汇编短 20 倍，提升效率，初期绑定 IBM 硬件
        • COBOL（1959 年）：由多方联合开发，目标“一次编写，到处运行”，通过专属编译器适配不同硬件
      • 后续发展：1960 年代起陆续出现 ALGOL、LISP、C、Python、Java 等语言，不断降低编程门槛、适配新技术
    • 编程语言抽象的意义与影响
      • 降低门槛：让非专家也能使用计算机，使其成为通用工具
      • 提升复杂度：支持开发更复杂程序
      • 硬件解耦：通过编译器实现硬件无关，升级硬件无需重写所有代码

    12. 编程原理 - 语句和函数¶

    • 编程语言的核心基础
      • 语句（Statements）
        • 定义：表达单个完整思想的指令，类比口语句子
        • 语法（Syntax）：规定语句结构与组合规则，违反则程序无法运行
      • 变量与赋值
        • 变量：抽象的内存地址，自定义唯一名称（如 apples、pears）
        • 赋值语句：将值赋予变量
    • 控制流语句（Control Flow Statements）
      • 作用：改变程序执行顺序，实现交互式逻辑
      • 常见类型：if 语句、while 循环、for 循环
    • 函数与抽象（Functions & Abstraction）
      • 函数意义：打包重复代码，隐藏复杂度，提升可读性和可维护性
      • 函数定义：含自定义命名（贴合功能）、外部传入的参数、return 返回值
      • 函数调用：通过函数名传入参数，支持嵌套调用
      • 模块化编程
        • 优势：拆分复杂程序为不超过 100 行的小函数，便于单人开发、团队协作
        • 库（Libraries）：专家编写测试的预制函数集合，涵盖各类功能，避免重复开发
    • 现代编程的核心
      • 抽象的力量：通过函数、库隐藏底层细节，专注问题解决而非硬件操作
      • 程序复杂度：现代软件（如浏览器）由数千个函数组成，模块化保障可维护、可扩展

    13. 算法入门¶

    • 算法
      • 定义：解决问题的具体步骤，是计算机科学的核心
      • 评估标准：执行步骤越少越高效，同时考量内存占用等因素
      • 意义：早于现代计算机出现，催生计算机科学这门学科
    • 排序算法
      • 常见类型：选择排序（Selection Sort）、归并排序（Merge Sort）
    • 图搜索算法
      • 图的定义：由节点（城市）和边（道路）组成，边带权重/成本（耗时、距离等）
      • 蛮力搜索法：穷举所有路径计算成本，时间复杂度 O(n!)，效率极低
      • Dijkstra 算法（Edsger Dijkstra 发明）
        • 核心思想：从起点出发，每次选成本最低的未访问节点，更新相邻节点最小成本
        • 执行步骤：初始化起点成本→选最低成本节点遍历边→更新相邻节点成本→标记已访问，重复至找到目标
        • 时间复杂度：原始 O(n²)，改进版 O(n log n + l)（n 为节点数，l 为边数）
    • 算法复杂度与大 O 表示法：描述输入规模与执行步骤的关系，用于量化算法效率

    14. 数据结构¶

    • 数据结构
      • 作用：结构化存储数据，方便检索、读取与操作，避免杂乱
      • 意义：算法的基础，合适的数据结构可大幅提升程序效率
      • 核心：通过不同组织方式，满足不同场景的存储与计算需求
    • 基础数据结构
      • 数组 (Array)、字符串 (String)、矩阵 (Matrix)
    • 复合数据结构
      • 结构体 (Struct)
    • 链式数据结构
      • 节点 (Node)、链表 (Linked List)、队列 (Queue)、栈 (Stack)
    • 树型数据结构
      • 树 (Tree)、二叉树 (Binary Tree)
    • 图数据结构 (Graph)
    • 总结
      • 高级结构：在基础结构上扩展出红黑树、堆等复杂结构
      • 语言支持：主流编程语言自带标准库（如 C++ STL、Java 类库），无需从零实现
      • 核心价值：合理选择数据结构，可简化编程、提升算法效率，是抽象分层的重要体现

    15. 阿兰·图灵¶

    • 阿兰·图灵生平基础
      • 基本信息：1912 年出生于英国伦敦，少年时期展现出极高的数学和科学天赋
      • 身份定位：计算机科学之父，现代计算理论的核心奠基人
    • 希尔伯特判定问题与早期理论突破
      • 希尔伯特判定问题
        • 提出者：德国数学家大卫·希尔伯特
        • 问题内容：是否存在通用算法，输入形式逻辑语句，可准确输出是或否的答案
        • 意义：计算理论早期核心问题，关系数学与计算的边界
      • 阿隆佐·丘奇的研究
        • 1935 年提出 Lambda 算子系统，证明无通用算法可解决所有逻辑问题
        • 局限：数学表达抽象复杂，难以推广理解
      • 图灵的并行研究
        • 同期独立提出假想计算装置图灵机
        • 计算能力与 Lambda 算子等价，模型更直观，成为后世主流计算模型
    • 图灵机原理与结构
      • 基本组成
        • 纸带：理论上无限长，用于存储输入符号和输出结果
        • 读写头：可读取、写入符号，也可左右移动一格
        • 状态变量：保存机器当前运行状态
        • 规则集合：根据当前状态和读取的符号，决定下一步动作
      • 允许的操作：写入符号、改变状态、移动读写头，可组合执行
      • 核心价值
        • 图灵机是通用计算模型，有足够时间和内存可执行任何可计算任务
        • 达到图灵机计算能力的系统称为图灵完备
        • 现代计算机、手机、嵌入式设备均为图灵完备
    • 停机问题与计算的极限
      • 停机问题定义
        • 给定图灵机程序描述和输入纸带，是否有通用算法可提前判断：机器会正常停机还是陷入无限循环
        • 意义：解决停机问题可提前规避程序死循环，避免无效等待
      • 图灵的反证法证明
        • 假设存在判定机器 H，可判断任意程序是否停机，输入 (程序 P，输入 I) 即可判定程序 P 输入 I 是否会停机
        • 基于 H 构造反向机器 Bizzaro，输入程序 P，将 (P,P) 传给 H；H 判定 P(P) 停机则 Bizzaro 死循环，反之则立刻停机
        • 将程序 Bizzaro 输入机器 Bizzaro 触发悖论，证明 H 无法正确判定停机问题
      • 结论
        • 停机问题不可解
        • 证明并非所有问题都可通过计算解决，计算存在天然边界
    • 丘奇-图灵论题
      • 提出者：阿隆佐·丘奇和阿兰·图灵
      • 核心内容：正式定义可计算性，统一计算模型的能力边界
      • 历史意义：奠定理论计算机科学的基础
    • 二战期间的密码破译贡献
      • 英格玛机：德军加密机器，靠齿轮和插板加密文本，缺陷是字母加密后不会是自身
      • 炸弹机 Bombe：图灵在波兰密码学家基础上设计，利用英格玛机缺陷缩小密码搜索范围
      • 战争影响：破解德军大量加密通信，提供关键军事情报，被认为将二战缩短数年
    • 战后学术与技术贡献
      • 早期计算机研发：参与设计曼彻斯特 Mark 1，是早期重要的存储程序计算机
      • 人工智能奠基：1950 年提出图灵测试，作为判断机器是否具备智能的标准，规则是文字对话无法区分人类与计算机即通过测试
      • 现代延伸：验证码 CAPTCHA 是反向图灵测试，用于区分人类与自动化程序
    • 图灵的人生悲剧
      • 时代背景：当时英国同性恋属违法行为
      • 遭遇：1952 年因入室盗窃案调查暴露性取向，被起诉定罪
      • 选择：被迫在入狱和激素治疗间二选一，选择后者以继续科研
      • 离世：1954 年服毒自尽，年仅 41 岁
    • 后世纪念与历史地位
      • 图灵奖：计算机科学领域最高荣誉，等同于诺贝尔奖
      • 历史定位：奠定计算理论、密码学、人工智能三大领域基础
      • 后世评价：开启数字时代的核心科学家，思想影响至今

    16. 软件工程¶

    • 软件工程引入
      • 背景：大型软件代码量巨大，单人无法完成
      • 定义：开发大型程序的工具与方法集合
      • 提出：Margaret Hamilton，用于阿波罗登月项目
      • 思想：提前预防问题，而非事后补救
    • 程序拆分与面向对象编程
      • 函数拆分：可协作，但数量过多仍难管理
      • 面向对象：将变量与函数打包成对象，形成层级
      • 本质：封装细节，提高抽象层级
      • 主流语言：C++、Java、Python、C# 等
    • API 应用程序编程接口
      • 定义：模块间交互的标准方式
      • 作用：隐藏内部实现，只需调用接口
      • 权限：public 公开调用，private 内部使用
    • IDE 集成开发环境
      • 定义：集编写、编译、调试、管理于一体的工具
      • 功能：语法高亮、错误检查、项目管理、调试
      • 价值：大幅提升编码与排错效率
    • 代码文档
      • 作用：方便理解、复用与协作
      • 形式：README 说明 + 代码内注释
      • 意义：降低维护与沟通成本
    • 版本控制
      • 核心：统一代码仓库，管理多人修改
      • 流程：检出 → 编辑 → 提交
      • 作用：避免冲突、支持回滚、记录修改人
    • QA 质量保证测试
      • 目的：模拟场景，提前发现并修复 bug
      • Alpha 版：内部测试，功能不全、bug 较多
      • Beta 版：公开测试，接近完成，收集外部问题

    17. 集成电路 & 摩尔定律¶

    • 分立元件时代与数字暴政
      • 时间：1940 年代~1960 年代中期
      • 特点：计算机由分立元件构成，需手工焊接
      • 代表：ENIAC 用大量真空管，焊点超 500 万
      • 困境：数字暴政——性能提升导致复杂度爆炸
    • 晶体管与第二代计算
      • 1950 年代中期商用，替代真空管
      • 更小、更快、更可靠，但仍是分立元件，未解决复杂度问题
      • 代表：IBM 7090，速度提升 6 倍，成本减半
    • 集成电路（IC）的诞生
      • 思路：把多个元件做在同一基底上，从根源解决数字暴政
      • 1958 年 Jack Kilby 做出首个 IC（锗材料）
      • 1959 年 Robert Noyce 用硅实现可商用 IC，被称为现代 IC 之父
    • 印刷电路板（PCB）
      • 用蚀刻线路连接芯片，实现批量生产、缩小体积
      • 与 IC 配合，彻底取代分立电路
    • 光刻技术
      • 制造 IC 的核心工艺，用光在硅晶圆上刻出精细电路
      • 可一次性做出数百万晶体管，切割封装成芯片
    • 摩尔定律
      • 1965 年由 Gordon Moore 提出
      • 趋势：每两年同面积芯片上晶体管数量大致翻倍
      • 带来更小、更快、更低功耗、更便宜的芯片
    • Intel 与微处理器（第三代计算）
      • 1968 年 Noyce 与 Moore 创立 Intel
      • 1971 年 Intel 4004，首款商用微处理器，把 CPU 集成在单块芯片
    • 晶体管密度飞速提升
      • 几十年间从数万激增至数十亿个
      • 光刻工艺不断进步，线宽大幅缩小
    • VLSI 与第四代计算
      • 晶体管过多，手工设计无法完成
      • 依靠 VLSI 软件自动设计芯片，开启第四代计算
    • 摩尔定律面临挑战
      • 光刻受波长限制，工艺逼近极限
      • 晶体管过小会出现量子隧穿、漏电
      • 实验室已实现更小制程，但大规模商用仍不确定

    18. 操作系统¶

    • 操作系统引入与诞生
      • 早期：单次运行 1 个程序，手动切换，效率低
      • 诞生：1950 年代，为解决人工瓶颈，管理程序运行
      • 定义：拥有硬件最高权限，开机首个运行，管控所有程序
    • 第一代：批处理操作系统
      • 核心：一次性提交多个程序，自动切换下一个，提升硬件利用率

    • 操作系统三大核心功能

      • 设备驱动：提供标准化接口，让程序适配不同外设
      • 多任务处理：CPU 按调度切换程序，避免 I/O 等待时闲置（1962 年 Atlas Supervisor 为首个）
      • 内存管理：分配隔离内存、支持动态分配与虚拟内存，Atlas 首个实现虚拟内存 + 内存保护
        • 虚拟内存：对地址虚拟化，程序视角内存连续，OS 完成虚拟→物理地址映射

    • 分时操作系统

      • 核心：CPU 按时间片轮转，支持多用户同时交互
      • 代表：1969 年 Multics，模块化但复杂
    • Unix 操作系统
      • 诞生：由 Dennis Ritchie、Ken Thompson 打造，简洁轻量
      • 架构：内核（核心底层）+ 配套工具（灵活扩展）
      • 内核恐慌：内核致命错误，系统无法恢复
    • 个人电脑时代操作系统
      • MS-DOS（1981）：体积小，无多任务、内存保护，易崩溃
      • 早期 Windows（1985）：无强内存保护，易蓝屏
    • 现代操作系统
      • 代表：macOS、Windows 10+、Linux、iOS、Android
      • 核心：支持多任务、虚拟内存、内存保护，保障程序稳定运行

    19. 内存 & 储存介质¶

    • 内存与存储的区别
      • 内存：易失性，断电丢失，速度快，存运行时数据
      • 外存储：非易失性，断电不丢，容量大、成本低，长期保存
    • 早期存储
      • 打孔卡/纸带：1940 年代，便宜但慢、一次性、不可改
      • 延迟线存储器：用电信号在介质中传播延迟存数据，只能顺序访问
      • 磁芯存储器：1953 年起普及，靠磁环磁化存 0/1，支持随机访问，可靠但贵
    • 磁性存储
      • 磁带：1951 年用于 UNIVAC，顺序访问，便宜适合归档
      • 磁鼓：早期高速存储，靠旋转读写，后被淘汰
      • 硬盘 HDD：1956 年 IBM 发明，容量大、成本低，靠旋转盘片+移动磁头读写
      • 软盘：便携磁性存储，1970–90 年代流行，容量小、速度慢
    • 光存储
      • CD、DVD 等，用激光识别光盘凹坑读写，适合影音和软件分发
    • 固态存储
      • 集成电路 RAM 取代磁芯内存
      • SSD 固态硬盘：无机械部件，速度快、抗震、无噪音
      • U 盘：便携固态存储
    • 内存层次结构
      • 速度越快 → 成本越高、容量越小
      • 用于平衡速度、成本、容量
    • 发展总结
      • 从机械到固态，体积更小、速度更快、成本更低
      • 整体呈指数级进步

    20. 文件系统¶

    • 核心引入

      • 上集：磁带、硬盘等可非易失性海量存储二进制数据
      • 本集：文件本质、文件格式、文件系统
      • 文件本质：存储设备上的二进制序列，承载文本、音频、图片、视频等

    • 文件格式

      • 定义：数据编码与组织规则，决定软件如何解析二进制
      • TXT 纯文本：用 ASCII 映射字符，无格式、无额外元数据
      • WAV 音频：文件头 + 采样数据，头信息包含格式、码率、声道
      • BMP 图片：文件头 + 像素数据，记录宽高、色深、RGB 信息
      • 共性：所有文件都是二进制，格式决定解析方式

    • 元数据与文件头

      • 元数据：描述数据的数据，记录文件属性
      • 文件头：位于文件开头，存放元数据，供软件识别类型与解析内容
      • 纯文本靠编码标准实现类似元数据的功能

    • 早期连续存储

      • 方式：文件首尾相连连续存放
      • 问题：硬件无文件概念，需目录文件标记起止、长度、信息
      • 目录文件存在最前端，管理所有文件信息

    • 平面文件系统

      • 特点：所有文件同一层级，无嵌套
      • 缺点：文件扩容易覆盖后续内容，管理文件数量有限

    • 现代文件系统优化

      • 分块存储：空间划分为固定大小块，文件分散存于多个块
      • 优势：支持扩容，简化管理，目录记录块编号
      • 碎片化：文件块分散存放，机械硬盘会降低读取速度
      • 碎片整理：重组连续块，提升机械硬盘速度，SSD 不需要

    • 分层文件系统

      • 结构：根目录 → 文件夹 → 文件，支持嵌套
      • 优点：便于分类管理，移动文件只改目录，不改数据
      • 主流系统 Windows、macOS、Linux 均使用

    • 文件删除原理

      • 仅删除目录记录，不立即擦除数据块
      • 未覆盖前可恢复，是数据恢复与取证的基础

    • 文件系统核心价值

      • 屏蔽底层硬件差异
      • 提供统一文件操作接口
      • 让用户简单直观管理数据

    21. 压缩¶

    • 核心引入

      • 上集：讲了文本、WAV、BMP 等简单但低效的文件格式
      • 本集：数据压缩，用更少位数表示数据，节省空间、加快传输
      • 分类：无损压缩、有损压缩，均通过消除冗余实现

    • 无损压缩

      • 特点：解压后数据与原文件完全一致
      • 游程编码：把连续重复数据记为「次数+数值」
      • 霍夫曼编码：高频数据用短编码，低频用长编码，靠霍夫曼树实现，需保存编码表
      • 常用格式：GIF、PNG、PDF、ZIP
      • 适用：文档、程序等必须完整无误的文件

    • 有损压缩

      • 特点：舍弃人不易感知的数据，压缩率更高
      • 音频：利用人耳听觉局限，保留关键频段
        • 代表：MP3，体积可缩小到原来的 1/10
      • 图片：利用人眼视觉局限，忽略细微颜色变化
        • 代表：JPEG，按 8×8 块压缩，删高频细节

    • 视频压缩

      • 结合图片压缩 + 帧间冗余
      • 利用连续帧的相似性，只存变化部分
      • 代表：MPEG-4，压缩比可达 20~200 倍
      • 过度压缩会出现失真、块效应

    • 总结

      • 压缩是现代存储与网络传输的基础
      • 无损保数据，有损提效率，视频兼顾时空冗余
      • 支撑流媒体、网络语音、高清传输等应用

    22. 命令行界面¶

    • 早期计算机的人机交互以机械和纸质为主
      • 最早的机械与机电设备使用齿轮、旋钮、开关进行输入输出
      • 早期电子计算机如 Colossus、ENIAC 依靠控制面板与接线操作
      • 程序输入耗时极长，输出主要依靠打印机，1820 年代巴贝奇就已为差分机设计打印机
      • 1950 年代后被打孔卡、磁带取代，同时出现指示灯做实时反馈
      • 这一时期的设计优先适配机器，人类使用成本高
    • 1950 年代末开始出现交互式人机交互
      • 小型计算机成本下降，使得人机来回交互成为可能
      • 大型机发展出多任务与分时系统，需要更方便的用户输入
      • 计算机开始使用键盘作为主要输入设备
    • 键盘从打字机发展而来并长期沿用 QWERTY 布局
      • 现代打字机由 Christopher Latham Sholes 在 1868 年发明
      • QWERTY 布局最初并非为防卡键，而是多次迭代的结果
      • 因用户习惯与转换成本，该布局沿用至今
      • 出现十指打字与盲打技术，大幅提升输入速度
    • 电传打字机成为早期计算机交互终端
      • 电传打字机本用于电报，可远距离传输文本
      • 被改造后成为计算机的输入输出设备
      • 形成命令行交互模式，用户输入指令，计算机文本回应
    • 命令行界面是长期主流的交互方式
      • 典型命令包括 ls、cat、finger 等
      • 1970 年代被屏幕终端取代，成为虚拟终端
      • 屏幕更高效、可编辑，迅速普及

    23. 屏幕 & 2D 图形显示¶

    • 早期屏幕与 PDP-1

      • 1960 年的 PDP-1 是早期图形计算机代表，键盘、电传打字机与屏幕分离
      • 早期屏幕主要用于跟踪程序运行（如寄存器值），而非输出最终结果，结果多打印到纸上
      • 屏幕更新快，适合显示临时值，避免浪费纸张和时间

    • 阴极射线管（CRT）与两种绘图方式

      • 原理：发射电子撞击磷光涂层发光，电子路径可通过磁场控制
      • 矢量扫描：引导电子束描绘形状，快速重复路径形成稳定图像
      • 光栅扫描：按固定路径逐行扫描（左上到右下），仅在特定点开启电子束绘制图形

    • 液晶显示器（LCD）与像素

      • LCD 采用光栅扫描，更新像素中红、绿、蓝子像素的亮度
      • 早期计算机因内存限制，很少使用像素：200×200 像素的黑白图像需 40,000 bit，超过 PDP-1 一半内存

    • 字符生成器与屏幕缓冲区

      • 为节省内存，早期计算机存储字符网格（典型 80×25）而非大量像素
      • 字符生成器（初代显卡）从内存读取字符编码，通过 ROM 中的点阵图案转换为光栅图形
      • 屏幕缓冲区：内存中专门用于图形的区域，程序修改其中的值即可更新屏幕显示
      • 局限：仅能绘制字符，后通过扩展 ASCII（如 IBM CP437）实现伪图形界面

    • 矢量图形与矢量命令画图

      • 原理：用线段定义所有图形，无需存储大量像素，节省内存
      • 矢量命令示例（来自 Vectrex）：reset（清屏、移动到原点）、MOVE_TO（移动绘图点）、INTENSITY（设置亮度）等
      • 优势：160 bit 即可绘制三角形，远高效于像素矩阵
      • 应用：1962 年 PDP-1 上的《Spacewar!》是最早的矢量图形游戏之一

    • Sketchpad 与光笔

      • 1962 年由 Ivan Sutherland 开发，是首个完整的交互式图形应用（CAD），后获图灵奖
      • 光笔：通过检测屏幕刷新时间确定位置，支持绘制、编辑图形
      • 功能：自动生成平行/等长/垂直线条、动态缩放、保存/复用设计库，是现代 CAD 的雏形

    • 位图显示与帧缓冲区

      • 1960 年代末出现，内存位直接映射到屏幕像素，支持任意图形
      • 帧缓冲区：存储像素数据的内存区域，早期用普通 RAM，后用显卡上的高速 VRAM
      • 灰度示例：8 位灰度屏用 0（黑）~255（白）表示强度，早期多为绿/橙色而非白色
      • 绘图实现：通过代码直接操作帧缓冲区，可实现画线、矩形等图形，可封装为函数复用

    • 图形库与抽象

      • 现代编程使用图形库提供的现成函数（画线、曲线、形状、文字），避免重复造轮子
      • 位图灵活性推动了交互式计算，但成本高昂，1971 年美国仅约 1,000 台计算机配备交互式图形屏幕

    • 总结

      • 从字符生成器到矢量图形，再到位图显示，图形技术逐步突破内存限制
      • Sketchpad 等先驱奠定了图形用户界面（GUI）的基础，为后续发展铺平道路

    24. 冷战和消费主义¶

    • 时代背景：1940 年代中期至 1970 年代中期，是计算机技术从诞生到成熟的关键 30 年，为个人电脑、万维网等后续发展奠定基础

      • 二战后冷战开启，美国政府向科学与工程领域投入大量资金，推动计算机技术快速发展
      • 计算机在战时已证明价值（如曼哈顿计划、破解纳粹通讯），因此获得重点支持，催生 ENIAC、EDVAC 等大型项目

    • 范内瓦·布什与 Memex 构想

      • 1945 年提出假想设备 Memex，可存储书籍、记录与通讯，通过关联轨迹快速检索，辅助人类记忆，直接启发 Sketchpad、oN-LINE 系统等后续里程碑
      • 推动建立美国国家科学基金会（NSF，1950 年成立），至今仍是美国科研资金的重要来源，助力美国科技领先

    • 1950 年代消费市场与日本半导体崛起

      • 晶体管收音机成为爆款：体积小、便携、耐用，相比真空管收音机更具优势，是当时的“现象级产品”
      • 日本从贝尔实验室获得晶体管授权（1952 年），索尼推出 TR-55 晶体管收音机（1955 年），凭借质量与价格优势，5 年内占据美国便携式收音机市场半壁江山，为日本半导体行业崛起埋下伏笔

    • 太空竞赛与集成电路发展

      • 1961 年苏联宇航员加加林进入太空，促使美国提出登月计划，NASA 预算增长近 10 倍，1966 年占联邦预算 4.5%
      • 阿波罗导航计算机是首个使用集成电路的计算机，满足太空任务对速度、体积、可靠性的严苛要求
      • 军事应用（如民兵、北极星核导弹系统）推动集成电路大规模生产，美国超级计算机（CDC、Cray、IBM 制造）进一步加速技术迭代，这些设备主要服务于政府与科研机构

    • 美国半导体行业转型与日本消费电子主导

      • 冷战消退后，美国半导体行业依赖的高利润政府合同减少，因忽视低利润消费市场，竞争力下降，大量公司裁员、合并或倒闭
      • 英特尔转型：从内存集成电路转向处理器，最终挽救公司；仙童半导体濒临破产后被收购
      • 日本企业（夏普、卡西欧等）凭借规模经济、质量提升与成本控制，主导 1970 年代手持电子计算器市场，进一步降低集成电路成本，催生微处理器（如 Intel 4004）与街机游戏、家用电脑（Altair 8800）、家用游戏机（Atari 2600）等新产品

    • 总结：政府与消费者共同推动计算机发展

      • 早期：政府资金（冷战、太空竞赛）支持技术研发，让计算机行业成熟到可商用
      • 后期：消费者购买商用产品（收音机、计算器、家用电脑等），推动技术普及与迭代
      • 延续至今：政府仍资助科研、采购超级计算机，消费者持续购买消费电子，驱动计算机技术高速发展

    25. 个人计算机革命¶

    • 个人计算机革命的背景

      • 1970 年代初，单芯片 CPU、低成本固态存储器（RAM/ROM）、磁带/软盘存储和改装电视显示器等技术成熟，使个人计算机从概念变为可行
      • 核心变化：计算机成本大幅下降，首次实现“一人一机”，无需分时共享，个人计算机时代开启

    • Altair 8800：首个商业成功的个人计算机

      • 1975 年亮相《Popular Electronics》封面，以 439 美元套件形式发售，需自行组装，通胀后约合如今 2000 美元
      • 销量达数万台，催生大量爱好者与周边配件（内存、纸带读取器、电传接口），但程序仍需用机器码编写

    • 比尔·盖茨、保罗·艾伦与 Altair BASIC

      • 两人为 Altair 8800 开发 BASIC 解释器，将高级语言转换为机器码，使非专业爱好者也能编程
      • 1975 年演示成功，Altair BASIC 成为微软首款产品，推动个人计算机软件生态发展

    • Apple-I 与家酿计算机俱乐部

      • 1976 年，史蒂夫·沃兹尼亚克在“家酿计算机俱乐部”展示自制计算机原型，可连接电视并提供文本界面
      • 史蒂夫·乔布斯提议出售组装好的主板，Apple-I 诞生，售价 666.66 美元，仍需用户自行添加键盘、电源和机箱

    • 1977 年“三位一体”：开箱即用的个人计算机

      • Apple-II：苹果首款完整系统，提供彩色图形与声音输出，销量数百万，推动苹果成为行业领先
      • TRS-80 Model I：Tandy 公司生产，售价仅为 Apple-II 的一半，销量火爆
      • Commodore PET 2001：一体化设计，集成计算机、显示器、键盘与磁带驱动器，模糊计算机与家电界限
      • 共同特点：均搭载 BASIC 解释器，催生消费软件行业（游戏、文字处理器等），1979 年的 VisiCalc（首个电子表格）成为“杀手级应用”

    • IBM PC 与开放架构的雪球效应

      • 1980 年，IBM 因忽略微型计算机市场，份额从 60% 降至 30%，组建“肮脏十二人”团队重新设计个人计算机
      • 1981 年发布 IBM PC，采用开放架构，使用 Intel 芯片与微软 DOS，支持第三方硬件/外设扩展
      • 开放架构催生“IBM 兼容”生态：第三方厂商（康柏、戴尔）生产兼容机，微软授权 MS-DOS，形成用户多→软硬件多→用户更多的雪球效应，IBM 前三年销量达 200 万台，超越苹果

    • 苹果的封闭架构与 Macintosh

      • 苹果选择“封闭架构”，自主设计硬件、操作系统与外设，控制用户体验与可靠性，是唯一在非“IBM 兼容”下保持显著份额的厂商
      • 1984 年发布 Macintosh，采用图形用户界面（GUI），提供优于 DOS 命令行的用户体验，为后续发展奠定基础

    26. 图形用户界面¶

    • 图形用户界面（GUI）的先驱与发展

      • 道格拉斯·恩格尔巴特（Douglas Engelbart）：现代 GUI 的先驱
        • 受万尼瓦尔·布什 Memex 构想启发，1962 年发表《增强人类智力》报告，提出用计算机作为交互工具增强人类智力
        • 1964 年与比尔·英格利希合作发明首个计算机鼠标，1968 年在“所有演示之母”中展示 oN-Line System，包含位图图形、视频会议、实时协作编辑、多窗口等超前功能
        • 1997 年获图灵奖，其团队成员后加入施乐 PARC
      • 施乐帕洛阿尔托研究中心（Xerox PARC）
        • 1970 年成立，1973 年完成 Xerox Alto，首个真正的 GUI 计算机，采用“桌面隐喻”与 WIMP 界面（窗口、图标、菜单、指针）
        • 1981 年推出 Xerox Star 系统，扩展桌面隐喻，引入“剪切/复制/粘贴”和“所见即所得（WYSIWYG）”，但因价格高昂（约合如今 20 万美元）销量惨淡

    • GUI 编程基础：事件驱动模型

      • 核心：程序通过 GUI API 创建窗口与组件（按钮、文本框等），代码响应用户事件（点击、滚动等）而非顺序执行
      • 示例：创建窗口与按钮，绑定“点击”事件到函数，触发时执行逻辑（如生成随机数、改变颜色）

    • 苹果与 GUI 商业化

      • 1979 年史蒂夫·乔布斯参观施乐 PARC，受 GUI 启发，苹果后续产品融入桌面隐喻（菜单栏、垃圾桶等）
      • 1983 年 Apple Lisa：首款搭载 GUI 和鼠标的苹果产品，价格高昂（约合如今 2.5 万美元），市场失败
      • 1984 年 Macintosh：价格降至约合如今 6000 美元，开售 100 天销量 7 万台，但初期软件生态薄弱，后因竞争加剧，乔布斯被逐出苹果

    • 微软与 GUI 普及

      • 1985 年 Windows 1.0：基于 DOS，界面简陋，开启与苹果的长期竞争
      • 1990 年代 Windows 3.1 后，微软开发独立 GUI 操作系统
      • 1995 年 Windows 95：重大重构，引入开始菜单、任务栏、文件管理器，支持多任务与受保护内存，占据近 95% 个人电脑市场
      • 1995 年 Microsoft Bob：将桌面隐喻极端化为虚拟房间，因过度设计失败，成为界面设计的反面案例

    • 总结与影响

      • 现代桌面 GUI 均源于 Xerox Alto 的 WIMP 范式，是数十年试错与自然选择的结果
      • GUI 降低了计算机使用门槛，推动个人电脑普及，同时仍在不断演进，以实现恩格尔巴特“增强人类智力”的愿景

    27. 3D 图形¶

    • 3D 图形基础：从 3D 到 2D 的投影

      • 3D 坐标：点由 X、Y、Z 三个坐标定义，需通过投影算法“拍平”到 2D 屏幕
      • 线框渲染：将 3D 点投影为 2D 点，再用线段连接，形成物体轮廓
      • 投影类型：
        • 正交投影：平行边在投影中仍保持平行，适合工程制图
        • 透视投影：平行线条向远处收敛，更符合人眼视觉，增强立体感

    • 3D 模型与网格

      • 三角形（多边形）：3D 模型的基本单元，三点唯一确定一个平面，是最小且稳定的几何形状
      • 网格：由大量三角形组成的集合，网格越密，模型表面越平滑，但计算量也越大
      • 网格简化：游戏开发者需在模型精度与性能间平衡，避免多边形过多导致帧率下降

    • 填充与抗锯齿

      • 扫描线渲染：1967 年诞生于犹他州大学，逐行扫描并填充多边形内像素
      • 填充速率：计算机填充多边形的速度，是衡量图形性能的重要指标
      • 锯齿与抗锯齿：
        • 锯齿：因像素离散导致的边缘粗糙感
        • 抗锯齿：根据多边形覆盖像素的比例调整颜色深浅，柔化边缘，提升视觉效果

    • 遮挡处理

      • 画家算法：按从远到近的顺序渲染多边形，近的覆盖远的，类似画家先画背景再画前景
      • 深度缓冲（Z-Buffering）：
        • 记录每个像素到摄像机的最近距离，渲染时仅保留更近的多边形，无需排序
        • 问题：当两个多边形距离完全相同时，会出现“Z 冲突”（闪烁）
      • 背面剔除：忽略朝向摄像机背面的多边形，将需处理的面数减半，提升效率

    • 光照与纹理

      • 平面着色：根据多边形表面法线与光源的夹角，为整个多边形赋予单一颜色，是最基础的光照算法
      • 高级着色：高洛德着色、冯氏着色等，通过在多边形表面渐变颜色，使模型更光滑
      • 纹理映射：将 2D 图像（纹理）映射到 3D 多边形表面，通过坐标对应关系，为每个像素赋予纹理中的颜色

    • 图形加速与 GPU

      • 并行计算：3D 渲染是高度并行的任务，适合同时处理大量相同计算
      • GPU（图形处理单元）：专为图形渲染设计的专用处理器，拥有大量核心，可并行处理数百万个多边形
      • 现代显卡：如 GeForce GTX 1080 TI 拥有 3584 个核心，每秒可处理数亿个多边形，大幅提升渲染效率

    28. 计算机网络¶

    • 计算机网络的诞生与早期发展

      • 背景：1970 年前计算机多为独立运行，随着大型机普及和个人计算机出现，数据与资源共享需求催生了早期网络
      • 局域网（LAN）：近距离计算机组成的网络，用于组织内部交换信息、共享外设（如打印机、存储），替代“球鞋网络”（人工搬运纸卡/磁带）
      • 以太网（Ethernet）：1970 年代由施乐 PARC 开发，至今仍广泛使用的局域网技术

    • 以太网核心机制

      • 共享媒介：多台计算机连接到同一条电缆，数据以电信号传输
      • MAC 地址：每台设备的唯一媒体访问控制地址，用于标识数据接收方，数据头部包含目标 MAC 地址
      • CSMA（载波侦听多路访问）：计算机监听共享媒介，空闲时传输数据，避免冲突
      • 冲突处理：
        • 冲突检测：多设备同时传输导致数据混乱，计算机可通过监听信号检测冲突
        • 指数退避：检测到冲突后，等待一段随机时间并重传；若再次冲突，等待时间指数级增长，减少网络拥塞

    • 冲突域与网络扩展

      • 冲突域：共享同一传输媒介的设备集合，设备越多冲突概率越高
      • 网络交换机：将大网络拆分为多个小冲突域，仅在必要时转发数据，提升效率
      • 互联网本质：由大量局域网通过交换机/路由器互联而成，实现跨网络通信

    • 路由与交换技术

      • 路由器：路由器（Router）是一种网络设备，它的核心作用是在不同网络之间转发数据包，并为数据选择最佳传输路径。

      • 交换方式：

        • 电路交换：早期电话系统采用，为通信分配专用线路，独占带宽但不灵活、成本高，适合高可靠性需求（如军事、银行）
        • 报文交换：类似邮政系统，报文经多个中间站点转发，可动态选择路由，容错性强，但大报文易堵塞链路
        • 分组交换（Packet Switching）：将大报文拆分为小数据包，每个包含目标地址，独立路由传输，高效且去中心化，是互联网的核心技术

      • 路由协议：路由器通过 ICMP、BGP 等协议交换信息，动态选择最优路径，实现拥塞控制与负载均衡

      • 跳数（Hop Count）：
        • 定义：报文/数据包从源到目标经过的路由器数量，每经过一个路由器，跳数加 1
        • 作用：用于检测路由问题（如路由环路），当跳数超过“跳数限制”时，数据包会被丢弃，避免无限循环

    • 互联网协议与发展

      • IP 地址：互联网协议定义的设备标识，用于路由寻址，如 172.217.7.238（Google 服务器）
      • ARPANET：首个分组交换网络，现代互联网的前身，由美国高级研究计划局（ARPA）资助，1974 年已连接多所大学与实验室
      • 规模增长：从几十台设备发展到近百亿台联网设备，物联网（IoT）进一步推动网络扩展

    29. 互联网¶

    • 数据从电脑到目标服务器的传输路径
      • 先连接局域网（LAN），即家里 / 工作室 WiFi 路由器下的所有设备
      • 再连接广域网（WAN），即 ISP 运营商的路由器（如 Comcast、AT&T）
      • 最终接入互联网主干，由高带宽巨型路由器组成
      • 数据包需多次跳转（多跳）才能到达目标服务器
    • traceroute 工具
      • 适用于 Windows、Mac、Linux 系统
      • 可查看数据包从本机到目标网络的传输路径
      • 能显示经过的路由器数量（跳数）和具体路由节点
    • IP 协议（互联网协议）
      • 定义互联网数据包的标准格式，核心是目标 IP 地址
      • 数据包结构：头部（元数据，仅含 IP 地址）+ 数据载荷
      • 局限性
        • 只能将数据包送到目标计算机
        • 无法确定交给计算机上的哪个应用程序
        • 不处理数据丢失、损坏问题
    • UDP 协议（用户数据报协议）
      • 运行在 IP 协议之上，属于传输层协议
      • 核心补充功能
        • 端口号：每款联网应用申请唯一端口（如 Skype 用 3478 端口），确保数据交给正确程序
        • 校验和：检测数据传输是否损坏
          • 发送方计算数据总和，16 位存储（超最大值则丢弃高位）
          • 接收方重复计算，对比一致则正常，否则丢弃数据包
      • 特点
        • 优点：简单、快速，开销小
        • 缺点：不确认送达、不纠正顺序、不重传丢失包
      • 适用场景：视频通话（Skype）、在线游戏等可容忍少量丢包的实时应用
    • TCP 协议（传输控制协议）
      • 运行在 IP 协议之上，与 IP 合称 TCP/IP，是互联网核心协议
      • 核心功能（继承 UDP + 新增可靠机制）
        • 端口号 + 校验和：与 UDP 一致，确保数据交给正确应用、检测损坏
        • 序号机制：给每个数据包分配唯一序号，接收方可重组乱序数据
        • ACK 确认机制：接收方成功收包后返回确认码，超时未收则重传
        • 拥塞控制：通过 ACK 成功率、往返时间，动态调整发送速率
      • 特点
        • 优点：可靠（无丢失、乱序）、可控（拥塞控制）
        • 缺点：开销大（ACK 使消息量翻倍）、速度比 UDP 慢
      • 适用场景：网页访问、邮件、文件下载等需数据完整送达的应用
    • DNS（域名系统）
      • 核心作用：将好记的域名（如 google.com）映射为 IP 地址（如 172.217.7.238）
      • 工作流程
        • 浏览器输入域名 → 向 ISP 的 DNS 服务器查询
        • DNS 服务器查询注册表，返回对应 IP 地址
        • 浏览器通过 IP + 端口号，发起 TCP 请求访问网站
      • 结构：采用树状结构，分散管理海量域名
        • 顶级域名（TLD）：最顶层，如 .com、.gov、.cn
        • 二级域名：顶级域名之下，如 google.com、dftba.com
        • 子域名：二级域名之下，如 images.google.com
      • 数据存储：分布式存储在多台服务器，不同服务器负责树状结构的不同部分
      • 错误场景：输入不存在的域名，会出现 DNS 失败错误（无法找到对应 IP）
    • OSI 模型（开放式系统互联通信参考模型）
      • 核心意义：将网络通信分层，每一层负责特定任务，实现抽象解耦，便于分工改进
      • 7 层（从下到上）
        • 物理层：负责传输物理信号（网线电信号、WiFi 无线电信号）
        • 数据链路层：操控物理层，保障局域网内通信
          • 包含 MAC 地址、冲突检测、指数退避机制
          • 负责媒体访问控制，解决局域网内设备冲突问题
        • 网络层：负责不同网络间的数据包路由、交换
          • 核心协议是 IP 协议
          • 路由器主要工作在该层级
        • 传输层：负责计算机之间的点到点数据传输
          • 核心协议是 UDP、TCP
          • 处理数据错误检测与恢复
        • 会话层：负责管理计算机间的连接（会话）
          • 通过 TCP/UDP 建立连接、传输数据、关闭连接
          • DNS 查询、网页访问均会经历完整会话流程
        • 表示层：负责数据格式转换、加密、解密、解码
          • 处理数据如何被解读，如 HTML 解码、图片编码、数据压缩
        • 应用层：直接为应用程序提供网络服务
          • 包含用户接触到的软件与功能，如浏览器、Skype、网页服务、视频流

    30. 万维网¶

    • 万维网（WWW）和互联网（Internet）不是同一个东西
      • 互联网是底层传输网络，万维网是运行在它上面的应用
      • 万维网是全球最大的分布式应用，通过浏览器访问
    • 万维网基础单元是网页，由超文本和超链接构成
      • 超链接可以从一个页面跳转到另一个页面，形成网状结构
      • 超文本概念最早由 Vannevar Bush 在 1945 年提出
    • 每个网页有唯一地址，叫 URL（统一资源定位符）
      • 访问网页时，先通过 DNS 把 URL 中的域名（如 thecrashcourse.com/courses 中的 thecrashcourse.com）转为 IP 地址
      • 再用 TCP 连接网页服务器，默认端口 80
    • 网页传输使用 HTTP 协议
      • 浏览器通过 HTTP 协议向服务器请求指定网页，HTTP 是专门用于传输超文本的协议
      • 最早只有 GET 指令，用来请求页面（如向服务器发送指令 “GET /courses”，请求 thecrashcourse.com 服务器上的 “courses” 网页）
      • 有状态码，200 表示成功，404 表示页面不存在
    • 网页用 HTML（超文本标记语言）编写
      • 由标签组成，比如 h1、a、li、ol 等
      • 可以配合 CSS、JavaScript 实现样式和交互
    • 浏览器用来请求、解析并显示网页
      • 第一个浏览器由 Tim Berners-Lee 在 1990 年开发
      • 他同时创造了 URL、HTML、HTTP
      • Mosaic 是第一个流行的图文浏览器
    • 搜索引擎用于在网上查找信息
      • 由爬虫、索引、搜索算法组成
      • Google 靠反向链接（backlinks）提升排名质量
    • 网络中立性（Net Neutrality）
      • 原则：所有数据包应被平等传输
      • 争议：是否允许 ISP 优先传输某些数据、限制其他数据
      • 支持者认为保护创新，反对者认为有技术和市场理由

    31. 计算机安全¶

    • 网络安全的核心目标
      • 保密性：仅授权人员可访问数据
      • 完整性：仅授权人员可修改数据
      • 可用性：授权人员可随时使用系统与数据
    • 常见攻击类型
      • 数据泄露：破坏保密性
      • 冒充发送信息：破坏完整性
      • 拒绝服务攻击（DoS）：通过大量虚假请求让服务不可用，破坏可用性
    • 威胁模型
      • 用于定义攻击者的能力、目标与攻击途径
      • 安全方案取决于所对抗的威胁类型
      • 不同威胁等级对应不同防护强度
    • 身份认证的三种方式
      • 你知道什么：密码、PIN、用户名
        • 最简单，但易被暴力破解
        • 4 位 PIN 只有 10000 种组合，计算机可瞬间试完
        • 复杂密码或多词组合可大幅提高安全性
      • 你有什么：钥匙、U 盾、手机令牌
        • 避免被猜中，通常需要物理接触
        • 可被复制、盗窃
      • 你是什么：生物识别，指纹、虹膜、面部
        • 安全性高，但设备昂贵
        • 识别是概率性的，可能出错
        • 生物特征无法重置，泄露后果严重
    • 多因素认证
      • 同时使用两种及以上认证方式
      • 大幅提升安全性，是重要账户的推荐方案
    • 访问控制
      • 认证后决定用户可操作的权限：读、写、执行
      • 通过权限列表（ACL）管理
      • Bell-LaPadula 模型
        • 不能向上读：低权限不能读高密级数据
        • 不能向下写：高权限不能写入低密级数据，防止泄密
    • 恶意软件与系统安全
      • 恶意软件可破坏底层信任，绕过认证与权限
      • 漏洞多来自代码实现错误
      • 安全内核：最小化可信代码，减少漏洞
    • 代码安全与审计
      • 开源代码便于独立审查
      • 第三方审计更容易发现漏洞
      • 安全会议如 DEF CON 用于交流攻防技术
    • 隔离机制
      • 目的：程序被攻破时限制损害范围
      • 沙箱：每个程序拥有独立内存区域
      • 虚拟机：一台电脑运行多个隔离系统
      • 一个程序崩溃不影响其他环境

    32. 黑客 & 攻击¶

    • 黑客分类与动机
      • 白帽：受雇寻找漏洞，修补安全问题
      • 黑帽：恶意攻击，窃取、利用、贩卖数据与漏洞
      • 动机：娱乐、牟利、社会政治目的
    • 社会工程学攻击
      • 网络钓鱼：伪造网站骗取账号密码
      • 假托：伪装身份骗取信息或修改配置
      • 木马：伪装成正常文件，实则安装恶意软件
    • 恶意软件类型
      • 窃取数据、密码
      • 勒索软件：加密文件索要赎金
    • 暴力破解与防御绕过
      • 暴力尝试所有密码组合
      • 系统会延时或锁定防御
      • NAND 镜像：物理复制内存，绕过等待限制
    • 缓冲区溢出
      • 输入超长数据，覆盖内存相邻内容
      • 可篡改权限、绕过登录、劫持系统
      • 防御：边界检查、地址随机化、金丝雀监测
    • 代码注入（以 SQL 注入为例）
      • 在输入中嵌入数据库指令
      • 可删表、窃取数据、添加管理员账户
      • 防御：过滤特殊字符、净化输入
    • 漏洞与攻击扩散
      • 零日漏洞：厂商未知的可利用漏洞
      • 蠕虫：自动在计算机间传播
      • 僵尸网络：控制大量电脑，用于 DDoS、挖矿、发垃圾邮件
    • 网络安全危害
      • 每年造成巨大经济损失
      • 威胁关键基础设施：电力、交通、通信
      • 网络战可瘫痪国家体系
    • 安全建议
      • 及时更新系统与软件
      • 开启多因素认证
      • 不随意点击可疑链接

    33. 加密¶

    • 密码学基础
      • 密码学：实现“秘密书写”，保护信息机密性
      • 明文：原始信息；密文：加密后的乱码
      • 加密：明文 → 密文；解密：密文 → 明文
      • 密码（Cipher）：加密算法；密钥（Key）：控制加解密的参数
    • 古典加密算法
      • 替换密码
        • 凯撒密码：字母统一偏移固定位数
        • 缺点：保留字母频率，易被统计破解
      • 移位密码
        • 按特定行列顺序重排字符
        • 密钥：网格大小、读取顺序
    • 机械加密：Enigma 机
      • 多转子 + 反射器 + 插板，实现复杂替换
      • 每输入一个字母，转子自动转动，替换规则变化
      • 加解密使用同一套初始配置
      • 缺陷：字母无法加密为自身，成为被破解关键
    • 现代对称加密
      • DES（1977）
        • 56 位密钥，2⁵⁶ 种组合
        • 1999 年可被暴力破解，不再安全
      • AES（2001）
        • 支持 128/192/256 位密钥，极难暴力破解
        • 按 16 字节分块，多轮替换与置换
        • 平衡安全性与性能，广泛用于 WiFi、HTTPS、文件加密
    • 对称加密特点
      • 收发双方使用相同密钥
      • 速度快，适合大量数据传输
    • 密钥交换：Diffie‑Hellman
      • 解决公网环境下安全共享密钥问题
      • 基于单向函数：正向易算，逆向极难
      • 原理：模幂运算（B^X mod M）
      • 双方各自生成私钥，交换中间值，最终算出相同共享密钥
    • 非对称加密（公钥密码）
      • 一对密钥：公钥（公开）+ 私钥（保密）
      • 公钥加密 → 仅私钥可解密
      • 私钥加密 → 仅公钥可解密（用于数字签名）
      • 作用：身份认证、防伪造、安全建立会话密钥
    • 典型非对称算法：RSA
      • 基于大整数分解难题
      • 用于签名、身份验证、协商对称密钥
    • 现代安全通信流程
      • 公钥密码验证身份
      • 密钥交换生成临时共享密钥
      • 使用 AES 等对称加密传输数据

    37. 机器人¶

    • 机器人定义与本质
      • 核心定义：由计算机控制，能自动执行一系列动作的机器
      • 关键特征：自动化、物理存在（区别于虚拟 bot/agent）
      • 形态多样：工业机械臂、无人机、医疗机器人、人形机器人等
    • 词源与文化起源
      • 词源：源自捷克语“robota”（强迫劳动），1920年捷克戏剧首次使用
      • 早期形象：电影/文学中常被描绘为高效、无情、无创造力的类人生物
      • 历史溯源：早于“机器人”术语的自动机（自动运行的机械装置，如1739年Vaucanson的机械装置）
    • 机器人伦理与争议
      • 致命自主武器：能自主杀人的机器人，被视为复杂棘手问题
      • 双面性：
        • 益处：挽救士兵生命、减少人员伤亡、可能抑制战争
        • 风险：缺乏人类判断与同情心、执行错误命令、战争环境下的不可控性
      • 伦理规范：
        • 阿西莫夫三定律（+零定律）：虚构的机器人行为准则，核心“不伤害人类”
        • 局限性：实践不足、存在歧义
        • 影响：激发大量科幻与学术讨论，催生机器人伦理会议
        • 创作初衷：反驳“机器人即威胁”的刻板印象，设想机器人为人类服务的正面形象
    • 核心思考
      • 技术两面性：机器人技术同样存在 benevolent（有益）与 malicious（有害）的应用可能
      • 责任：需审慎评估其潜力与风险，发挥创造力推动向善发展

    38. 计算机心理学¶

    • 人机交互与心理学基础
      • 核心目标：让系统有用、易用、好用，适配人类的认知与行为

    • 认知心理学：分块（Chunking）
      • 人类短期记忆：约 7±2 个单位
      • 分块：把信息拆成小而有意义的组（如电话号码分段）
      • 对计算机低效，但对人类极高效
    • 界面设计：直观功能（Affordances）
      • 定义：外观直接提示用法，无需说明书
      • 例子：按钮可点、把手可拉、平板可推
      • 反例：需要文字说明的门 → 设计失败
    • 认出 vs 回想（Recognition vs Recall）
      • 认出（看图/图标）远易于回想（记命令）
      • 图标、菜单、图形界面 → 大幅降低使用门槛
    • 兼顾新手与专家
      • 好界面提供多条路径完成任务
      • 例子：复制粘贴 = 菜单点选 + 快捷键
    • 情感计算（Affective Computing）
      • 目标：让计算机感知、理解、适应用户情绪
      • 输入：语音、面部、心率、出汗等生物特征
      • 应用：智能教育、情绪安抚、用户体验优化
    • 计算机媒介沟通（CMC）
      • 包含：同步（视频、直播）、异步（邮件、社交）
      • 特点：线上更易自我暴露、分享私密信息
    • 增强凝视（Augmented Gaze）
      • 解决：视频时视线不看镜头的问题
      • 效果：提升参与感、信任感、沟通效果
    • 人机交互（HRI）
      • 研究人类与机器人的互动方式
      • 人类会自然用社交规则对待机器人
      • 恐怖谷（Uncanny Valley）：越像人越不自然，会引发不适
    • 伦理与责任
      • 算法可影响情绪、行为、决策（如社交平台内容推送）
      • 设计必须考虑：公平、隐私、情绪操控、透明度
      • 最终目标：提升可及性与幸福感，让技术向善

    39. 教育科技¶

    • 教育技术基础
      • 计算机极大提升了信息的创造与传播能力
      • 教育技术目标：支持学习，提高效率与效果
      • 从纸笔、广播、电视到现代智能系统，技术长期辅助教育
    • 观看教育视频的有效学习方法
      • 调整播放速度，保证理解与思考时间
      • 适时暂停，自问自答，预测内容
      • 动手练习示例与习题，主动学习效果显著提升
    • MOOC 大规模开放在线课程
      • 2012 年被称为 MOOC 元年
      • 早期多为教授讲课录像，未颠覆传统大学
      • 面临规模大、师资少、反馈难、批改难等问题
    • 人机结合的教育解决方案
      • 学生互评 + 技术辅助，提升批改与反馈效率
      • 算法自动匹配学习伙伴、分组与资源
      • 部分客观题与写作可由AI自动评分，准确度接近人类
    • 智能辅导系统
      • 基于AI，提供个性化学习路径
      • 核心组件
        • 域模型：用规则表示知识点、解题步骤与常见错误
        • 学生模型：记录掌握情况，追踪学习进度
      • 贝叶斯知识追踪
        • 估算学生是否掌握某项技能
        • 考虑已学会概率、猜测概率、失误概率、学习中掌握概率
        • 根据答题情况动态更新学生模型
    • 教育数据挖掘
      • 收集百万级学习者行为数据
      • 分析常见错误、难点、学习习惯
      • 用于优化课程、个性化推荐与自适应学习
    • 未来教育技术方向
      • 教学虚拟代理：用自然语言互动，建立信任与陪伴
      • 多设备学习：桌面、平板、手机、沉浸式大屏
      • 虚拟现实与增强现实：提供沉浸式体验
      • 脑机接口学习：直接从大脑读取或写入知识

    40. 奇点，天网，计算机的未来¶

    • 课程总结
      • 从晶体管、逻辑门讲到计算机视觉、机器学习、机器人等领域
      • 回顾计算机发展史中的重要先驱与贡献者
      • 希望观众能深入理解计算机科学并激发学习与职业兴趣
    • 普适计算
      • 愿景：计算机融入所有物品，无处不在且自然隐形
      • 核心思想：技术融入日常生活，使用时无需刻意感知
      • 与当前模式对比：摆脱专注使用设备，实现无感交互
    • 人工智能发展
      • AI 已在特定领域表现出色，如驾驶、翻译、游戏
      • 通用人类级别的人工智能仍有很长距离
      • 未来 AI 更可能作为工具增强现有设备与系统
    • 智能水平与奇点
      • 目前计算机算力大致接近老鼠，远低于人类
      • 按发展趋势，未来算力可能超越全人类总和
      • 技术失控式智能爆发被称为奇点
      • 部分专家认为复杂度提升会放缓发展速度
    • 技术性失业
      • 自动化长期替代重复性劳动，历史上多次出现
      • 工作可分为手工/认知、常规/非常规四类
      • 易被自动化：常规手工、常规认知、部分非正规手工
      • 短期内相对安全：非正规认知类工作，如教师、艺术家、科学家
      • 影响：大规模失业与经济转型，长期可能创造新就业与更高生活水平
    • 人类与技术融合
      • 超人类主义：人机结合成为改造人，增强智力与身体
      • 脑机接口、可穿戴设备已开始模糊人机边界
      • 数字永生：意识上传至计算机，实现数字化存在
    • 计算机的长远未来
      • 计算机可能比人类存在更久
      • 可适应太空环境，进行星际探索与殖民
      • 延续人类探索与创造知识的使命
    • 近期可预见技术趋势
      • VR/AR、自动驾驶、无人机、服务机器人进入主流
      • 互联网持续演进，出现新服务与媒介形式
      • 新编程语言、硬件加速神经网络与图形计算
      • 个人电脑向无处不在的虚拟助手转型
    • 未覆盖领域
      • 加密货币、无线通信、3D 打印、生物信息学、量子计算
    • 结尾寄语
      • 正处于计算机黄金时代，创新空间巨大
      • 鼓励观众学习计算机知识，参与技术变革，用科技改善世界
