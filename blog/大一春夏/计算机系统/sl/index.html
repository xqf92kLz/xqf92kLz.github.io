    一、 课程基本信息与考核要求¶

    • 教学团队与课程定位：本课程为《计算机系统 Ⅰ》，由沈浩霆和卢立老师主讲，带有三位助教（冯恺睿等）。该课程将传统的数字逻辑、计算机组成原理等课程进行了融合压缩，旨在为后续的系统Ⅱ（操作系统）和系统Ⅲ（体系结构）打下硬件基础。
    • 成绩构成：
      • 平时作业 (15%)：共 8 次，每次 2 分。迟交每天扣除 5%。
      • 实验 Lab (50%)：课程极其强调实践（Talk is cheap, show me the code），包含多次Lab和一个Project。迟交每周扣除 25%。
      • 期末考试 (35%)：全英文试卷，因此必须掌握核心的专业英文词汇（如 Register, Memory 等）。
    • 学术诚信（非常严格）：严禁抄袭代码或让他人代写。特别注意：严禁使用 AI（如 ChatGPT、Copilot）直接生成核心硬件代码或实验报告。首次发现抄袭本次实验记0分，第二次发现课程总评不超过59分。允许使用 AI 辅导 Debug 或解释报错。
    • 实验验收 (验收)：提交代码和报告后，必须向助教进行代码设计的讲述与验收。助教会提问以确认是你独立完成（防AI代写），回答不出可能会扣分。

    二、 计算机系统基础理论 (理论课核心)¶

    1. 为什么学习计算机系统？ 学习系统课程是理解编译器、并行计算以及 AI/ML 新时代底层架构的基础。它可以帮助你理解软硬件的交界面，写出更高效、更不易出错的程序，而不只是做一个浮于表面的“API 调用者”。

    2. 程序是如何运行的？

    • 从代码到机器码：我们用 C 语言等高级语言写出的代码（算法+数据结构），计算机底层是无法直接看懂的。代码需要经过编译器 (Compiler) 翻译，先转换成汇编语言 (Assembly)（如 addi r5, r0, 10），最后完全转化为包含操作码和操作数的 0/1 二进制机器码 (Binary/Machine code)，以此对应底层硬件电路的通断电。

    3. 冯·诺依曼架构 (Von Neumann Architecture)

    • 这是现代计算机的经典基础架构，核心思想是存储程序 (Stored-program)。
    • 三大核心组件：
      1. CPU (中央处理器)：负责数学运算和控制。
      2. Memory (内存/主存)：同时存放“指令 (Code/Instruction)”和“数据 (Data)”。
      3. I/O (输入/输出设备)：用于与外界交互。
    • 为什么要采用这种架构？ 因为 CPU 的计算速度极快，而 I/O 设备（人机交互）极慢。为了解决这个巨大的速度鸿沟 (Gap)，系统一次性将程序和数据加载到内存中，CPU 随后只与高速的内存进行数据交互，不被外部低速输入打断，从而最大化资源利用率。

    4. 内存 (Memory) 与地址

    • 基本单位：最小存储单元是比特 (bit，0或1)。基本寻址单元是字节 (Byte，大写B)，1 Byte = 8 bits。
    • 地址空间：内存中每个字节都有一个唯一的地址。系统位数决定了地址总数，例如 32位系统最多有 \(2^{32}\) 个地址（约 4GB 容量），而 64 位系统则有海量的地址空间。
    • 代码与数据分区：为了防止 CPU 混淆“指令”和“数据”，操作系统在内存中会将代码段 (Code/Text) 和数据段 (Data) 分别存放在不同的地址区域。

    5. CPU 内部结构

    • 由于内存相对 CPU 还是不够快，CPU 内部集成了更高速的组件：
      • Registers (寄存器)：极其昂贵但速度与 CPU 一致的微小内存，用于存放当前单次运算急需的数据。通用寄存器称为 GPR。
      • PC (Program Counter, 程序计数器)：记录程序当前执行到了内存中的哪一行（哪个地址）。
      • IR (Instruction Register, 指令寄存器)：存放当前正在执行的那条指令。
      • ALU (Arithmetic and Logic Unit, 算术逻辑单元)：真正负责加减乘除和逻辑运算的模块。
      • Control Unit (控制单元)：它负责解码“当前指令寄存器”中的机器码（基于比特位的 0/1 组合），将指令翻译成具体的动作，并向 CPU 内部的各个硬件组件发送相应的电信号控制指令。
    • 指令执行周期：取指 (Fetch) → 解码 (Decode) → 执行 (Execute) → 访存 (Memory Access) → 写回 (Write Back)。

    6. 计算机演进与图灵机

    • 物理形态演进：算盘 → 机械齿轮计算器 → 真空管 (如世界上第一台通用电子计算机 ENIAC，占满整个屋子) → 晶体管 → 集成电路 (IC) → 现代微处理器。摩尔定律指出单位面积晶体管数量呈指数级增长。
    • 图灵机 (Turing Machine) 模型：它是现代计算理论的基石。其核心概念是：用有限的硬件资源和有限的存储状态，去处理无限长的输入信息流。

    三、 实验课实操技能 (Lab 0-1 & 0-2 核心)¶

    实验课是本门课的重中之重，前期主要包含环境配置、电路仿真和硬件描述语言入门。

    1. 实验环境配置

    • 操作系统：强烈推荐使用 Linux 环境（统一使用 Ubuntu 22.04 或 24.04）。Windows 用户通过 WSL (Windows Subsystem for Linux) 安装，Mac 用户使用虚拟机。
    • 终端与包管理：需要掌握基础的 Linux Bash 命令行（如 cd, ls）以及使用 apt 进行软件安装。在权限不足时，需使用 sudo 提权。
    • Git 版本控制：代码全托管于浙大的 Git 平台。需要掌握 git clone（下载仓库）、git pull（拉取云端最新更新）、git add、git commit 以及 git push（提交代码）。
    • IDE 编辑器：推荐使用 VS Code，并利用其 Remote 插件直接连接到 WSL 内部进行代码编写和终端控制，避免跨系统复制文件的麻烦。

    2. Lab 0-1: 逻辑电路仿真

    • SPICE 仿真：用于底层的电气特性模拟。实验中演示了用 SPICE 仿真反相器 (Inverter) 的电压传输特性，了解真实的硬件中逻辑 0 和逻辑 1 对应的电压阈值范围。
    • Logisim-evolution：这是一款可视化的 EDA 工具，用于绘制数字逻辑电路原理图并进行交互式仿真。在实验中需要亲手绘制指定电路，并保存为 .circ 格式工程文件。

    3. Lab 0-2: FPGA 与 Verilog HDL 入门 (极重要)

    • Verilog 是硬件描述语言 (HDL)

      ，不是编程语言！

      • 核心思想：在写代码前，脑子里一定要先有电路图！ 不能把 Verilog 当成 C 语言来写。它是用来“描述”一根根电线和逻辑门是如何连接的。

    • 基础语法：

      • module / endmodule：定义一个电路模块（类似 C 的函数，但它是物理存在的模块）。需要声明 input 和 output 端口。
      • wire：定义一根内部的物理导线。电气特性规定：一根 wire 可以连接到多个输入端（即驱动多个负载），但有且仅能有一个信号源（不能被多次驱动/多重赋值，否则会短路报错 multi-driven）。
      • assign：用于给导线赋值（也就是将导线连接起来）。这种连接是物理的、并行的，没有 C 语言那种从上到下的顺序概念。
      • 基本逻辑门运算符：~ (非 / NOT)，& (与 / AND)，| (或 / OR)。可以直接用这些符号组合成逻辑表达式（如真值表推导出的卡诺图表达式）。

    • 仿真与上板 (Verilator & Vivado)：

      • Verilator：用于在电脑里通过 C++ 模型来模拟 Verilog 电路的运行。需要编写 Testbench（测试激励文件，用于输入测试信号），运行后会生成波形图 (Waveform) 供查看和验证逻辑是否正确。
      • Vivado：用于真实的 FPGA 硬件开发。它会将 Verilog 综合 (Synthesis) 并转换为底层硬件能理解的比特流 (Bitstream) 文件，最终烧录到实际的 FPGA 开发板上运行。

    一、 程序的执行与冯·诺依曼架构¶

    1. 从代码到机器指令 高级语言（如 C、Java）为了让人类容易理解而设计，但机器只能看懂 0 和 1。一段代码需要经过编译器 (Compiler) 等工具的翻译，先变成汇编语言（如 addi r5, r0, 10），最后转化为机器语言（0 和 1 组成的机器码）。 在 RISC-V 等精简指令集架构中，每条指令的长度和格式是固定的（例如操作码在前，操作对象在后），这种规整的 0/1 排列能完美对应底层电路的通断电。

    2. 冯·诺依曼架构的核心

    • 历史背景：第一台类似冯·诺依曼架构的电子计算机是 ENIAC，诞生于二战期间，最初由美国陆军资助，用于计算复杂的导弹弹道。早期的机器计算需要人工去接电线，而冯·诺依曼架构改变了这一点。
    • 核心思想 (Stored-program)：将“指令（要执行的动作）”和“数据（操作的对象）”都存储在内存 (Memory) 中。
    • 为什么这么设计？ 因为 CPU 的计算速度极快，而 I/O（输入/输出）设备的速度极慢。为了防止 CPU 被慢速的 I/O 拖累，系统一次性将数据和程序加载到内存，CPU 只与高速的内存进行数据交互，充分利用计算资源。

    3. 厨房生动比喻：CPU 是如何工作的？ 老师用厨房做了一个非常形象的类比，帮助理解 CPU 各部件的功能：

    • 内存 (Memory) = 厨房货架。货架上放着“食谱（指令，如炒菜、洗菜）”和“食材（数据，如西红柿、鸡蛋）”。
    • CPU (中央处理器) = 厨师 + 灶台。早期运算单元和控制单元是分开的，后来集成在了一块芯片上。
    • 控制单元 (Control Unit) = 厨师。负责判断当前该去拿什么食材、使用什么锅具。
    • 算术逻辑单元 (ALU) = 灶台/锅炉。真正负责“炒菜”（执行数学和逻辑运算）的地方。
    • 通用寄存器 (GPR) = 临时放菜的盘子。用于存放刚切好的菜或刚炒好的半成品（临时计算数据）。
    • 指令寄存器 (IR) = 厨师眼前的菜谱架。专门存放厨师“当前正在看的那一步食谱（当前执行的指令）”，外部用户不可见。
    • 程序计数器 (PC) = 进度记录本。记录当前执行到了第几行食谱。每次开机，PC 都会清零，从内存的固定地址（如启动程序）开始按顺序读取。

    4. 指令执行的五大生命周期 CPU 运行的本质就是不断循环以下五个步骤：取指 (Fetch) → 解码 (Decode) → 执行 (Execute) → 访存 (Memory Access) → 写回 (Write Back)。

    5. 拓展知识：物理地址与逻辑地址的映射 在内存访问中，程序通常使用的是逻辑地址，而硬件底层映射到的是乱序的物理地址。 这样做有三大好处：

    • 保证各个程序的内存访问时间（体验）平均。
    • 防止物理存储单元被集中频繁使用而损坏（磨损均衡）。
    • 安全防护：防止攻击者通过观察程序执行时间的快慢（侧信道攻击）来推测密码存放的物理位置并窃取数据。

    二、 信息的表达：模拟信号 vs 数字信号¶

    1. 模拟信号的缺陷 (Analog Signal) 模拟信号在时间和取值上都是连续的（如自然界的温度、风速）。但在传递过程中极易受噪声干扰。老师用“上课传悄悄话”举例：悄悄话传递时，由于环境噪音，传到最后一个人时信息通常面目全非，且接收者无法准确还原原话。

    2. 数字信号的优势 (Digital Signal) 数字信号在取值上是离散的（如只有 0 和 1），同步数字信号在时间（采样周期）上也是离散的。 优势在于抗干扰能力强。如果规定只有 A、B、C、D 四个有效值，即使信号在传输中因为噪音变得模糊（如听起来像 A 的杂音），接收端也能强制将其“校准”回标准的 A。这就是数字信号能去除噪音、完美还原的本质。

    3. 硬件中的电压阈值 (Threshold) 在实际电路的金属导线中，电容和电阻会导致电压衰减（0.9V 传过去可能变小）。为了保证系统稳定：

    • 输出端要求严：发信号时，要求高电平必须 >0.9V，低电平 <0.1V。
    • 输入端要求宽：接收信号时，只要 >0.6V 就认为是1，<0.4V 就认为是 0。 如果落在中间的模糊地带（如 0.5V），则被视为无效的噪音数据。

    4. 为什么选用二进制？ 数学上，自然常数 e 作为进制底数是最高效的，但现实中造不出来。三进制（正电压、零电压、负电压）在苏联时期曾被研究过，但工业界最终选择了二进制，因为 0 和 1 完美对应电路的“断”和“通”，物理实现成本最低、最稳定。

    三、 进制转换与数据宽度¶

    1. 多项式表达法 任何进制（R 进制）的数值都可以展开为多项式：系数乘以 \(R\) 的指数次方。小数点左边指数为正（0, 1, 2...），小数点右边指数为负（-1, -2...）。

    2. 十进制转二进制的算法原理

    • 整数部分（除 2 取余法）：不断除以 2，本质上是在探测该数字是否包含 \(2^0, 2^1, 2^2...\)。除几次到 0，就说明最高位是 2 的几次方。余数从下往上读（或从右往左写）。
    • 小数部分（乘 2 取整法）：例如 0.6875，不断乘以 2，如果结果大于 1，说明包含 \(2^{-1}\)（即 0.5），则该位置 1，并扣除 1 继续乘。整数部分从上往下读。

    3. 十六进制与二进制的极速转换 十六进制（0-F）和八进制（0-7）是程序员常用的进制。因为 \(16 = 2^4\)，二进制和十六进制可以完美地实现“四位对一位”的直接映射（如 1100 直接对应十六进制的 C），极大简化了书写和转换。

    4. 存储单位的差异

    • 1 KB = \(2^{10}\) = 1024 字节。
    • 1 MB = \(2^{20}\) 字节（约等于 100 万）。
    • 1 GB = \(2^{30}\) 字节（约等于 10 亿）。 随着容量变大，二进制容量和十进制整十倍（\(10^3, 10^6\)）的误差会越来越大（例如 GB 级别误差接近 7.3%），这也是为什么买的硬盘在电脑里显示容量会“缩水”的原因。

    四、 二进制的算术运算及硬件代价¶

    1. 加法与减法

    • 加法很简单，逢二进一。注意要有进位输入（Carry in）和进位输出（Carry out）的概念。
    • 减法与机械转盘比喻：二进制中 0 - 1 = 1（需要向前借位）。老师用密码锁/机械转盘举例：数字转盘从 000 往前退一格（减1），会变成 999。同理，二进制里 0 减去 1，当前位变成最高值 1，同时产生一个向高位的借位信号（Borrow out）。

    2. 乘法与除法的硬件差异

    • 乘法：其实就是根据乘数是 1 还是 0，把被乘数抄下来或者全置 0，然后进行位移 (Shift) 并相加。乘法在硬件中可以完全转化为加法器和移位操作。
    • 除法（极其昂贵）：除法需要类似于人工算竖式的“试商”过程。硬件必须先去尝试比较除数和被除数的大小，不够减再移位。这种“尝试与比较的判断过程”在硬件设计中开销极大。因此除法器的电路复杂度远超加法器和乘法器。

    五、 原码与补码的引入 (下节课前瞻)¶

    在处理负数时，最符合直觉的做法是原码 (Sign-Magnitude)：最高位用 1 表示负，0 表示正，后面的位表示数值（例如 0011 是 3，1011 是 -3）。 但原码有两个致命问题：

    1. 正负零问题：0000 表示 +0，1000 表示 -0，同一个 0 有两种表达，给计算逻辑带来极大负担。
    2. 硬件开销大：如果用原码，CPU 做加法时必须额外设计专门处理符号位的电路，符号位和数值位不能统一用加法器计算，需要两套逻辑。

    为了解决这个问题，老师在课程最后“挖了个坑”，引出了补码 (Two's Complement) 的概念：通过基于“取模运算”的数学原理，把符号位和数值位统一起来处理。这部分也是下节课的重点内容。

    第一部分：理论课（计算机底层信息的表达）¶

    1. 为什么不使用“原码”而使用“补码”？ 计算机底层运算依赖于 0 和 1。最初直观的数值表达方式是原码 (Sign-and-Magnitude)，即最高位代表正负号（0 为正，1 为负），其余位代表数值。但原码有两大致命缺陷：

    • 0 的表示不唯一：存在 +0 (0000...) 和 -0 (1000...) 两种表示方式，这给计算机在跨越 0 点判断时带来了巨大的逻辑负担。
    • 硬件开销大：如果使用原码，硬件必须配备两套运算单元，一套专门处理符号位，另一套处理数值位。

    2. 补码 (Two's Complement) 的数学原理与特性 为了统一加减法并消除双零问题，现代计算机采用基于取模运算 (Modulo) 的补码设计。

    • 核心定义：在补码中，最高位不再单纯是符号位，而是带有负权重的数值位。以 \(n\) 位系统为例，最高位代表 \(-2^{n-1}\)，而其余所有低位都代表正的权重。
    • 取模的优美之处：有限的硬件资源无法表示无限的自然数。通过取模运算（如超过最大值后从最小值重新开始），可以将无限的数值折叠到有限的闭环中。这保证了在正负数边界加减法时，数学逻辑是连续且等价的（例如，在 4 位系统中，7 再加 1 发生截断后变成 -8，这在底层加法器看来是一致的操作）。
    • 转换口诀：正数的补码与原码相同。负数从原码转补码的操作是：除符号位外取反，然后再加 1。
    • 极值范围：在补码中，如果全为 0，值就是 0。如果最高位是 1 其余全 0，这是系统能表示的最小负数（例如 4 位系统的 1000 代表 -8）。最大的负数是全 1（代表 -1）。

    3. 乘法与符号位扩展 (Sign Extension)

    • 溢出 (Overflow)：在加法中，如果两个正数相加，结果的最高符号位翻转成了 1（变成了负数），说明超出了硬件表达上限，发生了溢出，系统会通过专门的 Flag 标志位来判断和处理。
    • 位扩展：当需要把一个短位数的数值放到长位数的寄存器中（例如 4 位扩展到 8 位），必须进行符号位扩展。正数高位全补 0，负数高位全补 1，这样可以保证其真实数值在补码下绝对不变。
    • 在进行带符号的二进制乘法时，被乘数和乘数必须先通过符号位扩展补齐到目标结果的位宽，然后通过左移（等同于乘以 2 的次方）和相加来完成硬件乘法。

    4. IEEE 754 浮点数标准 (极重要) 为了在有限资源下表示更大范围和更高精度的实数，计算机采用了类似科学计数法的浮点数标准（如单精度 32 位）。内存强制划分为三段：1 位符号位 (Sign, S)，8 位指数位 (Exponent, E)，和 23 位尾数/小数位 (Fraction, M)。

    • 常规数 (Normalized Values)：当指数位非全 0 且非全 1 时，为常规数。
      • 隐藏的 1：为了极致节省内存，常规数尾数前的整数部分默认永远是 1.。因此，内存中不需要存这个 1，只存小数点后面的尾数，计算时硬件会自动把 1 补上。
      • 指数偏移量 (Bias)：真实物理指数 = 机器码存的指数 - 偏移量。8 位指数的偏移量是 \(127\) (\(2^{8-1}-1\))。
    • 非常规数 (Denormalized Values)：当指数位全为 0 时触发。
      • 此时，尾数前的整数部分默认为 0. 而不是 1。这种设计专门用于极度靠近 0 的微小数字，解决了常规数逼近 0 时密度剧烈跳变的问题，保证了 0 附近数值的平滑过渡（渐进式下溢）。
    • 特殊值 (Special Values)：当指数位全为 1 时触发。
      • 无穷大 (Infinity)：尾数全为 0 时，表示溢出或无穷大（例如任何数除以 0）。
      • 无意义数值 (NaN, Not a Number)：尾数不为 0 时，表示数学上无法计算的无意义操作（如负数开根号）。NaN 参与任何运算都会报错，但在底层比较时，它被定义为大于 Infinity。
    • 拓展应用：AI 大模型在进行 16 位浮点压 8 位整数的“量化”操作时，舍弃尾数会导致微小的精度损失，这种误差累积后会导致模型输出概率排名变化，从而引起推理能力下降。

    一、 为什么需要浮点数？¶

    在硬件资源有限的情况下，传统的定点数或整数存在很大局限。我们需要一种新的表达方式来满足以下需求：

    1. 极大的表示范围与极高的精度：用有限的位数（如 32 位）既能表示天文数字，又能表示极微小的小数。
    2. 处理极值与无意义操作：系统需要一种特殊的状态来表示“无穷大”（如除以 0 的结果），或者告知系统“该操作无意义/无法计算”。
    3. 零点附近的稠密度：在数轴上，数值越大（如几十亿），我们对小数部分的精度要求就越低；但在越靠近 0 的地方，我们需要数值的分布越稠密、越精确。

    二、 IEEE 754 标准基础与内存布局¶

    目前的浮点数标准是由 William Kahan 在 1976 年设计，并于 1985 年被采纳的 IEEE 754 标准。 浮点数的数学表达类似于科学计数法：\((-1)^S \times M \times 2^E\)。 在内存中，浮点数被严格划分为三段，按“影响力从大到小”排列：

    1. 符号位 (Sign, S)：排在最高位。0 表示正数，1 表示负数。
    2. 指数位 (Exponent, E)：排在中间。它决定了数值的量级（大小）。
    3. 尾数/小数位 (Fraction, M)：排在最后。它决定了数值的精度。 为什么这么排？ 因为在比较两个浮点数大小时，符号位影响最大，其次是指数，最后才是尾数。这种排列方式让硬件在比较大小时非常高效。

    三、 浮点数三大分段的底层设计细节 (极重要)¶

    1. 指数位 (Exponent) 与偏移量 (Bias)

    • 设计反直觉点：指数位没有采用补码来表示正负指数，而是把所有的机器码当作“无符号正整数”处理。
    • 为什么不用补码？ 如果用补码，机器在比较大小时需要额外的硬件逻辑去判断符号。直接当成无符号数处理，硬件比较器可以直接比较大小，效率极高。
    • 偏移量 (Bias)：为了表示负指数，标准引入了偏移量。真实物理指数 = 机器码的无符号值 - 偏移量。对于 8 位指数位（如单精度浮点数），偏移量固定为 \(127\) (\(2^{8-1}-1\))。例如，机器码如果是 140，真实指数就是 \(140 - 127 = 13\)。

    2. 尾数位 (Fraction) 与隐藏的 1

    • 极致的硬件抠门：在科学计数法中，规范的数字整数部分永远是 1.（如 \(1.01 \times 2^N\)）。既然正常情况下整数部分永远是 1，计算机为了极致压榨硬件资源，在内存中根本不存这个 1，只存小数点后面的部分。
    • 这就相当于用同样的内存线路，白嫖了 1 位的精度。在硬件 ALU 进行计算时，电路会自动把这个 1. 补回去。

    四、 浮点数的分类与边界情况¶

    机器会根据“指数位”的特征，将浮点数分为三大类：

    1. 常规数 (Normalized Values) 当指数位不是全 0，也不是全 1 时，就是常规数。遵守上述的“偏移量”和“隐藏的 1”规则。

    • 触发条件：当指数位 exp 的比特位既不全为 0，也不全为 1 时。
    • 表达特性：它的指数真实值 \(E = Exp - Bias\)（减去固定的偏移量），且尾数的前面存在一个隐藏的 1.（即真正的尾数 \(M = 1.xxx...\)）。由于科学计数法下常规数首位必定是 1，所以它在物理内存中被省去不存，从而为计算机“白嫖”了一位额外的精度。

    2. 非常规数 (Denormalized Values) - 填补零点鸿沟

    • 触发条件：当指数位 exp 全为 0 时。
    • 特性变化：此时，尾数前面的隐藏位不再是 1，而是变成了 0（即 0.xxx）。并且它的真实指数固定为 -126（即 \(1 - Bias\)）。
    • 为什么要有非常规数？ 在常规数下，能表示的最小正数是 \(1.0 \times 2^{-126}\)。如果不加干预，比它小的值只能是 0。这会导致 \(1.0 \times 2^{-126}\) 与 0 之间的距离，比它与下一个最小数 \(1.1 \times 2^{-126}\) 之间的距离大得多，造成零点附近的密度发生剧烈跳变。引入非常规数后，整数部分变成 0.，使得数值可以平滑、均匀地逼近 0（称为渐进式下溢），保证了微积分等数学计算在 0 点附近的连续性。
    • 正负零：当指数全 0，尾数也全 0 时，根据符号位 s 的不同，系统会存在 \(+0\) 和 \(-0\) 两个值。

    3. 特殊值 (Special Values) - 处理溢出与数学无意义操作

    • 触发条件：当指数位 exp 全为 1 时。

    • 无穷大 (Infinity, \(\infty\))：当尾数位 frac 全为 0 时触发。表示计算溢出（例如非零数除以零）。分为正无穷和负无穷。

    • 无意义/非数 (NaN, Not a Number)：当尾数位 frac 不全为 0 时触发。表示数学上无法定义的非法操作（如负数开根号、无穷大减无穷大）。NaN 参与任何运算都会报错，但在底层硬件逻辑强制比较大小时，系统会判定 NaN 大于 Infinity。

    五、 浮点数的缺陷与拓展认知¶

    1. 精度损失的本质 十进制中很简单的有限小数，如 \(0.2\) (1/5) 或 \(0.1\) (1/10)，转换成二进制后会变成无限循环小数。由于浮点数的尾数位数是有限的（如 23 位），多余的部分会被强制截断（四舍五入），这必然导致精度损失。

    • 前沿应用举例：老师特意提到现在的 AI 大模型推理。为了压缩模型体积，常把 16 位浮点数参数“量化”为 8 位。这会导致尾数被大量截断，微小的精度损失层层累积后，会改变模型最终输出的概率排名，导致 AI 推理能力下降。

    2. 浮点数分布与人类感知的哲学对应 浮点数在数轴上的分布呈现对数特性：在 0 附近极度密集，数值越大则越稀疏。老师以此做了一个生动的哲学拓展：人类感知世界也是呈对数特征的。

    • 时间感知：10 岁时过 1 年（占人生的 10%）觉得无比漫长；40 岁时过 1 年（只占人生的 2.5%）觉得转瞬即逝。
    • 听觉感知：人耳听声音的分贝也是对数系统。既能听到极微小的呼吸声（接近 0 点的高稠密度），也能承受比呼吸声强几亿倍的汽车喇叭声（大数值区的稀疏度）。这就是浮点数设计非常贴合自然规律的优美之处。

    一、 浮点数特性与程序数据基础 (前半节课收尾)¶

    在课程的前半段，老师对之前两周的“数据表示（主要是浮点数和整数）”进行了收尾和复习：

    • 浮点数运算的反直觉陷阱：在 C 语言等高级语言中，浮点数加法是不满足数学上的“结合律 (Associativity)”的。由于浮点数在相加时会存在精度丢失和舍入（例如大数吃小数），相同的几个浮点数，不同的相加顺序可能会得出完全不同的结果。
    • 特殊浮点数 NaN (Not a Number)：当指数位全为1，且小数部分非全 0 时，代表系统遇到了无法处理的无意义操作（如对负数开根号），表现为 NaN。
    • 数据宽度与字长 (Data Width and Storage)：
      • 基本单位：最小的单位是比特 (bit，小写 b，值为 0 或 1)，8 个比特组成一个字节 (Byte，大写 B)。
      • 字长 (Word Size)：对于指针和地址而言，字长决定了机器的虚拟地址空间大小。在典型的 32 位机器中，地址空间被死死限制在 4GB；而高阶的 64 位系统则支持高达 \(1.8 \times 10^{19}\) 字节的海量地址空间。
    • 多字节的存储顺序 (Endianness)：当一个数据占多个字节时，内存有两种存放规矩：
      • 大端序 (Big Endian)：最高有效字节存放在最低的内存地址中（如网络传输协议、Mac）。
      • 小端序 (Little Endian)：最低有效字节存放在最低的内存地址中（如常见的 x86 架构）。

    二、 开启新篇章：数字逻辑基础 (Foundations of Digital Logic)¶

    后半节课正式下沉到了偏物理的硬件和电路领域，讲解计算机如何通过电信号实现数学逻辑。

    1. 基本逻辑运算与门电路 (Logic Gates)

    • 三大基本操作：
      • 与 (AND)：用点 (\(\cdot\)) 表示，全部为真才为真。
      • 或 (OR)：用加号 (\(+\)) 表示，有真即为真。
      • 非 (NOT)：用上划线或波浪号 (\(\sim\)) 表示，取反。
    • 真值表 (Truth Table)：用于穷举逻辑函数所有可能的输入组合及其对应输出结果的表格。
    • 拓展逻辑门 (XOR, NAND, NOR)：
      • 异或门 (XOR)：老师特别指出，XOR 的本质可以理解为奇偶校验 (Parity check)，当输入的信号中 1 的个数为奇数时输出 1，为偶数个时输出 0。
    • 逻辑门的完备性：AND、OR、NOT 这三个基础门可以组合表示出所有的逻辑操作。同样，仅使用 NAND（与非）或仅使用 NOR（或非）也可以组合拼凑出世界上所有可能的逻辑电路，这为底层芯片的大规模流片制造提供了数学支撑。

    2. 集成电路 (IC) 的物理与电气特性 (极重要) 代码中的 0 和 1 落到物理世界上，本质就是导线里的电压高低。

    • 场效应晶体管 (FET)：现代集成电路主要基于 CMOS (互补金属氧化物半导体) 技术，它互补结合了 PMOS 和 NMOS。老师还科普了目前工业界为了防止漏电流，广泛使用了先进的 FinFET (鳍式场效应晶体管，长得像鱼鳍) 结构。
    • 逻辑电平与“禁区” (Logic Levels & Forbidden Zone)：
      • 供电电压通常称为 \(V_{CC}\) 或 \(V_{DD}\)。
      • 物理电压并不是完美的 0V 和 5V。为了容忍电气噪声，系统规定了明确的电压阈值：要想被认定为“高电平 (1)”，电压必须大于 \(V_{IH}\)；要被认定为“低电平 (0)”，电压必须小于 \(V_{IL}\)。
      • 禁区 (Forbidden Zone)：介于 \(V_{IL}\) 和 \(V_{IH}\) 之间的中间电压区域被称为禁区。落在这个区间的信号被视为不可靠的噪音。这种冗余设计赋予了数字电路极强的抗干扰（噪声容限 Noise Margin）能力。
    • 物理损耗与延迟：
      • 传播延迟 (Propagation delay)：电信号流经物理门电路不可避免会产生时间的滞后。
      • 跳变时间 (Transition time)：电压从 0 变到 1（上升时间 / 充电），或从 1 变到 0（下降时间 / 放电），绝不是瞬间完成的，而是需要一个爬坡过程，且上升和下降的速度往往不同。
      • 功耗 (Power dissipation)：电流流过晶体管产生的热量损耗。
    • 扇入与扇出 (Fan-in and Fan-out)：
      • 扇入 (Fan-in)：一个逻辑门电路能够接入的输入端数量（像扇子一样汇聚进来）。
      • 扇出 (Fan-out)：一个逻辑门的输出端，可以同时连接（驱动）下一级逻辑门输入端的最大数量。一拖多时，驱动的下游负载越多，产生的物理延时就越大。
