    前置知识¶

    Linux Ubuntu¶

    • 权限与软件管理 (Sudo & APT)

      • sudo (SuperUser DO)：

        这是 Linux 里的“至尊通行证”。在任何指令前加上 sudo，系统就会以管理员（root）身份执行它。

        例子：sudo mkdir /system_folder（在系统受保护区域创建文件夹）。

      • apt (Advanced Package Tool)：

        这是 Ubuntu 的内置“应用商店”命令行版。

        • sudo apt update：更新商店的货架清单（获取最新软件列表）。
        • sudo apt install <软件名>：安装指定的软件。

        在 Linux 中，git 是开发者最常用的工具之一。在 Ubuntu 中安装它后，你可以克隆（下载）开源项目，或者管理自己的硬件设计代码。

        假设你现在需要安装 git（开发中常用来管理代码版本）。按照 Ubuntu 的规范，你通常需要先更新软件列表，然后再执行安装。

        • 更新列表：sudo apt update
        • 执行安装：sudo apt install git

    • -y：它的全称通常是 --yes。它的核心作用是自动回答“是” (Yes)。比如 sudo apt install git -y。

    • wget：World Wide Get 的缩写。功能是从网络上下载文件。比如 wget https://example.com/file.zip。

      • 重命名下载：使用 -O 参数。例如：wget -O my_logisim.jar <下载链接>。这样下载下来的文件名就是你指定的，而不是一长串复杂的原始名。
      • 断点续传：使用 -c 参数。如果下载几百 MB 的 Vivado 安装包时断网了，wget -c <链接> 可以从上次断开的地方继续，不用从头再来。

    Logisim¶

    一个逻辑仿真器。它假设所有的导线要么是 0，要么是 1，不考虑中间过程。它很快，适合设计复杂的电脑 CPU 架构。

    • 手形工具 (The Poke Tool)

      这是最常用的工具。点击左上角工具栏中的小手图标。

      • 作用：当你使用它点击输入引脚（如开关）时，可以手动切换它的状态（从 0 变 1，或从 1 变 0）。
      • 视觉反馈：你会发现导线的颜色随之改变。

    • 导线颜色的秘密

      Logisim 用颜色来告诉你电路中电流的“性格”：

      • 深绿色：代表低电平（Logic 0）。
      • 浅绿色：代表高电平（Logic 1）。
      • 蓝色：代表未知状态（通常是因为没接线）。
      • 红色：代表冲突（报错！比如两个输出连在了一起）。

    • 查看组件属性 (Attribute Table)

      当你选中一个门电路或引脚时，左下角会出现一个表格：

      • Facing：改变组件的方向（朝东、南、西、北）。
        • North (北)：输出在上，输入在下。
        • South (南)：输出在下，输入在上。
        • East (东)：默认方向，输出在右，输入在左。
        • West (西)：输出在左，输入在右。
      • Number of Inputs：改变逻辑门的输入端数量（比如把 2 输入与门改成 5 输入）。
      • Label：给你的输入输出起名字，比如 "Reset" 或 "Clock"。

    • 自动组合分析 (Combinational Analysis)

      如果你在窗口顶部的菜单选择 Window → Combinational Analysis：

      • 你可以输入真值表，Logisim 会自动为你生成对应的逻辑电路。
      • 反之，如果你画好了电路，它也能帮你推导出复杂的逻辑表达式。

    • 时钟信号 (Clock Signal)

      在时序逻辑电路（比如计数器）中，你需要一个不断跳动的信号。

      • 操作：在工具栏找到小正方形里有个波形的图标。
      • 功能：它可以按照你设定的频率（Hz）自动在 0 和 1 之间切换，不需要你手动去点。
      • 快捷键：按 Ctrl + K 可以开启或停止时钟仿真。（或在菜单中选择 Simulate → Ticks Enabled）

    • 仿真速度与步进 (Ticks & Frequency)

      如果你的电路运行太快看不清过程，可以在 Simulate 菜单里调整 Tick Frequency。

      你也可以选择 Step Simulation (Ctrl + I)，让电路一次只运行一个“节拍”，这在排查复杂逻辑错误（Debug）时非常有用。

    • 从 Logisim 到 Verilog

      当你使用 Logisim-evolution 绘制好电路后，你可以直接导出硬件描述语言（HDL）代码。

      1. FPGA 菜单：在顶部菜单栏找到 FPGA > Synthesize & Download。
      2. 选择语言 (Hardware description language used for FPGA-commander)：通常我们会选择 Verilog，它是目前工业界最流行的硬件编程语言之一。
      3. 生成代码：点击 Execute 后，Logisim 会为你创建一个 .v 文件。

      这个 .v 文件包含了你刚才画的所有逻辑。我们可以把这个文件带回 Vivado 中进行编译。

      当 Logisim 导出 Verilog 时，它并不会只给你一个 main.v。为了保证电路在硬件上能跑通，它会生成一个层级结构：

      • gates/ 文件夹：包含了最基础的积木。比如 AND_GATE.v 里面定义了与门的行为，OR_GATE.v 定义了或门。

      • circuit/main.v：这是你的“组装说明书”。它会告诉系统：“拿一个 gates 里的与门出来，编号叫 u1，然后用 wire 把它的输出连到另一个或门上。”

    Ngspice¶

    一个电路模拟仿真器。它考虑电阻、电容、晶体管的物理特性。它比较慢，但它是确保芯片在工厂里能被实际制造出来的关键。

    • 输入：一个名为 网表 (Netlist) 的文本文件（通常以 .sp 或 .cir 结尾）。这个文件描述了电路里有什么元器件（比如电阻、晶体管）、它们是怎么连的，以及施加了什么样的电源。
    • 处理：它利用复杂的数学方程（线性代数和微分方程）来模拟电流在电路中的流动。
    • 输出：一组随时间或电压变化的数据点。你可以用这些数据画出波形图，观察电压的波动。

    在 Lab 0-1 中，Ngspice 被用来模拟反相器 (NOT Gate) 的 电压传输特性 (VTC)。VTC (Voltage Transfer Characteristic) 描述的是，当你往电路输入一个电压 (\(V_{in}\)) 时，输出电压 (\(V_{out}\)) 会发生什么变化。

    • 这种“模拟级别”的仿真能让你看到逻辑门内部最真实的物理表现，而不是简单的“0”和“1”。

    • Ngspice 会“连续记录”电压的变化。

    • 横轴是输入电压 \(V_{in}\)，纵轴是输出电压 \(V_{out}\)。对于一个理想的反相器，它的 VTC 曲线像一个阶梯：当输入很低时，输出牢牢保持在高电平；当输入达到某个点时，输出突然“跳水”跌到低电平。

    • 确定性区 (Deterministic Regions)：当输入电压很低（接近 0V）或很高（接近 5V）时，输出电压非常稳定。这时我们能百分之百确定逻辑状态。

      不确定区 (Indeterminate Region)：在中间某个电压点（比如 2.5V 左右），输出电压会发生剧烈变化。在这个区域，电路非常脆弱，一点微小的噪声就可能让系统产生错误的判断。

      开关速度：曲线越“陡峭”，说明反相器切换逻辑的速度越快，性能越好。

    • 放大效应：在反相器的 VTC 曲线中，中间那段非常陡峭的部分就是高增益区（放大区）。在这个区域，输入电压 \(V_{in}\) 哪怕只变化了 0.1V，输出电压 \(V_{out}\) 可能会瞬间跨越 3V 甚至更多。这种“小变大”的比例就是增益（放大倍数）。当信号进入这个高增益区时，反相器会迅速做出剧烈反应，把缓慢的变化变成极快的跳变。

    Verilog¶

    一种 硬件描述语言 (HDL, Hardware Description Language)。虽然它看起来像 C 语言或 Python，但其本质完全不同。

    • 描述而非执行：普通编程语言是让 CPU 按照顺序一步步执行指令；而 Verilog 是在描述电路的结构。当你写代码时，你实际上是在画一张包含逻辑门（与、或、非）和导线的蓝图。
    • 并行性：在 Verilog 中，所有的电路模块都是同时工作的。这就像一台机器里的齿轮，只要动力一进来，所有齿轮都会同时转动，而不是等第一个转完第二个才转。

    写 Verilog 前脑子里要先有电路，用简洁的表达式（如 &, |, ~）来描述清晰的结构。

    Verilator¶

    Verilator 是一个将硬件语言（Verilog）翻译成软件语言（C++）的工具。

    • make：按照 Makefile 里的默认流程，把 Verilog 编译成可执行文件。

      • Makefile 包含了一系列规则。每条规则告诉计算机：如果要得到某个“目标”（比如仿真程序），需要哪些“依赖文件”（比如你的 main.v），以及执行什么“命令”。

        在你的实验中，Makefile 主要负责以下三件事：

        1. Verilation：调用 verilator 将 Verilog 翻译成 C++。

        2. Compilation：调用 g++ 把生成的 C++ 变成可执行的二进制文件。

        3. Execution & Trace：运行程序，并产生波形文件（.vcd）。

          .vcd： Value Change Dump（数值变化转储）。它以文本形式记录了在仿真过程中，每一个信号（比如 I0, I1, O）在每一个时间轴节点上的电平变化（是从 0 变到了 1，还是从 1 变到了 0）。

    • make wave：发生的流程是

      1. 仿真程序运行，把所有的信号跳变写进 Testbench.vcd。
      2. GTKWave 打开这个 .vcd 文件，把枯燥的文本数据转化成直观的波形图。

      （如果你运行 make wave，通常不需要手动先运行一次 make，因为 make wave 内部已经包含了编译的步骤）

      在 GTKWave 中，你通常需要完成以下操作：

      • 在左侧树状栏找到 top → dut（你的电路模块）。
        • 最外层的盒子 (top)：这是 Verilator 为你生成的整个 C++ 类实例（在 testbench.v 中通常对应 module Testbench）。它是仿真的顶层入口。
        • 里面的盒子 (dut)：dut 代表 Device Under Test（被测器件）。在你的 testbench.v 中，有一行代码 main dut(...)，这表示你在测试平台里“插上”了你设计的 main 模块，并给它起名叫 dut。
      • 选中 I0, I1, I2 和 O，点击底部的 Append 将它们加入波形显示区。
      • 观察 O 的高低电平跳变是否符合你在 Lab0-1 中写的真值表。

    Vivado¶

    一款专业的 集成设计环境 (IDE)。如果 Verilog 是剧本，那么 Vivado 就是导演和制片人，负责把剧本变成真实的电影。

    • 仿真 (Simulation)

      手动给输入信号（比如开关）提供不同的电平，然后观察输出信号（比如灯）的波形图。

      仿真结果通常以 时序波形图 的形式呈现：

      • 横轴：代表时间（通常以纳秒 ns 为单位）。
      • 纵轴：列出了你代码中的所有信号（S, I, D, L）。
      • 波形：高位表示逻辑 1，地位表示逻辑 0。

    • 综合 (Synthesis)：Vivado 会像“翻译官”一样，把你写的 Verilog 代码（如 assign O = I1 & I2）转换成由具体逻辑门（与门、或门、选择器等）组成的 网表 (Netlist)。在这个阶段，Vivado 并不关心芯片的长相，它只关心逻辑上的连接关系。

      • 当你完成 Run Synthesis 后，Vivado 会生成网表。你可以通过以下操作直观地看到它：
        • 在 Flow Navigator 中找到 Synthesis → Open Synthesized Design。
        • 点击 Schematic（原理图）。
        • 现象：你会看到一个类似电路图的界面。这里的每一个方块都是 FPGA 里的真实资源（比如 LUT 或寄存器），它们之间的连线就是根据你的 assign 语句生成的。

    • 实现 (Implementation)：

      • 布局 (Placement)：根据你的网表，把逻辑单元（比如 LUT）放置在 FPGA 芯片内部最合适的物理坐标上。
      • 布线 (Routing)：在已经摆好的元器件之间寻找最短、最快的连线路径。

    • 生成比特流 (Bitstream)：生成一个二进制文件（通常是 .bit 后缀）。这个文件本质上是一张“配置表”，告诉 FPGA：哪些开关该闭合，哪些方块该激活。当你把这个文件下载进去，FPGA 就会瞬间“变身”成你设计的那个电路。

    • Sources（源文件管理）面板

      当你点击 Add Sources 时，Vivado 会让你从三个选项中选一个。选错了，文件就放错了“抽屉”，系统就找不到它：

      • Add or create design sources：这是放你的 .v 逻辑代码的地方（比如你的报警器主程序）。它是硬件的“灵魂”。

        这是你的 .v 逻辑文件（会被变成硬件）。

        • .v 文件：Verilog，规定逻辑连接

          这是你的电路逻辑蓝图。

          • 作用：它描述了电路的“大脑”。比如：如果你输入 A 和 B，它应该输出一个 A 与 B 的逻辑结果。
          • 内容：里面写的是 module、input、output 以及 assign 逻辑运算（如 &, |, ~）。
          • 特点：它只负责逻辑，不关心实物。它知道有一个信号叫 led_out，但它不知道这个信号最后会点亮开发板上哪颗灯。

      • Add or create simulation sources：这是放 _tb.v（Testbench）的地方。记住，仿真文件千万不要放进 Design Sources，否则在生成比特流时会报错，因为测试代码是无法转换成真实电路的。

        • .v Testbench 文件 文件：为了进行仿真，你需要编写一个特殊的 Verilog 文件，叫做 Testbench。它不描述电路，而是描述 实验过程。比如：
          1. 在 0ns 时，把所有开关都设为 0。
          2. 在 10ns 后，把总开关 S 拨到 1。
          3. 在 20ns 后，把传感器 I 也拨到 1。

      • Add or create constraints：这是放 .xdc 引脚约束文件的地方。

        • .xdc 文件：Xilinx 约束文件 (Xilinx Design Constraints)，规定哪个信号接哪个物理插孔
          • 作用：它负责把 .v 文件里的虚拟信号“绑”到 FPGA 芯片真实的金属引脚上。
          • 内容：通常包含引脚编号（如 PACKAGE_PIN H17）和电平标准（如 IOSTANDARD LVCMOS33）。
          • 特点：没有它，你的代码就只是一个“空想”，无法指挥硬件。
          • 想象你在 .v 文件里定义了一个输出信号叫 O。 在 .xdc 文件里，你会写一行代码，告诉 Vivado：“请把信号 O 连接到开发板上那个编号为 J15 的拨码开关上。”

      • Top Module（顶层模块）

        • Vivado 的运行逻辑是：从 Top Module 开始，递归地寻找它内部提到的所有子模块。
        • 在 Vivado 的 Sources 面板中，你会看到文件的层级关系：被设为 Top 的文件图标上会有一个小金字塔或三层方块的符号。它通常位于文件树的最顶端。

    • 在 Flow Navigator（左侧导航栏）中：

      1. Project Manager: 查看项目概况。
      2. Simulation: 点击 Run Simulation 进入波形图界面，验证逻辑。
      3. Synthesis: 点击 Run Synthesis，Vivado 会尝试把你的代码翻译成逻辑门（网表）。
        • Open Synthesized Design 门级视图：
          • 在这里，你看到的是逻辑门（如 LUT、Carry Lookahead）。
          • 它不关心芯片长什么样，只关心逻辑是否正确。
      4. Implementation: 点击 Run Implementation，进行布局布线。
        • Open Implemented Design 物理视图：
          • 在这里，你会看到一张巨大的 FPGA 芯片鸟瞰图。
          • 你会发现你的逻辑变成了芯片上成千上万个小点中的几个。
          • 你可以看到信号是如何穿过芯片内部的导线，最终走到你在 .xdc 里指定的那个引脚上的。
      5. Program and Debug: 最后一步，生成比特流（Generate Bitstream）并烧录到开发板。
