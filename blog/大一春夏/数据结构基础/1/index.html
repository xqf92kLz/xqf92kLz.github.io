    Chapter 2: Algorithm Analysis¶

    什么是算法？分析什么？¶

    • 算法的定义 (Algorithm)：算法是一个能够完成特定任务的有限指令集。它必须满足五大条件：
      1. 输入 (Input)：0 个或多个外部输入。
      2. 输出 (Output)：至少产生 1 个输出。
      3. 确定性 (Definiteness)：每一条指令必须清晰且无歧义 (clear and unambiguous),。
      4. 有限性 (Finiteness)：在所有情况下，算法必须在有限的步骤内终止。
      5. 有效性 (Effectiveness)：指令必须足够基础，原则上可以通过纸笔手工执行。
    • 程序与算法的区别：程序是用特定的编程语言编写的，且不一定需要有限（例如操作系统可以无限运行下去）；而算法可以用人类语言、流程图、伪代码等表示，它代表的是一种逻辑表达。

    渐近表示法 (Asymptotic Notation)¶

    为了描述当数据量趋于无穷大时，运行时间的增长趋势，引入了渐近表示法,：

    • 大 \(O\) (Big-O)：上限 (Upper bound)。表示 \(T(N)\) 的增长速度不快于 \(f(N)\)（\(T(N) \le c \cdot f(N)\)）。虽然上限可以写得非常大（如 \(O(N)\) 算法写成 \(O(N^3)\) 也不违背定义），但通常选择最逼近的那一个,。
    • 大 \(\Omega\) (Big-Omega)：下限 (Lower bound)。表示增长速度不慢于 \(g(N)\)。
    • 大 \(\Theta\) (Big-Theta)：严格约束 (Exact bound)。既是上限也是下限，但实际中较难精确界定，平时最常用的是大 \(O\)。
    • 小 \(o\) (Little-o)：严格上限。即严格小于，不包含等于的情况。
    • 常见增长率比较：常数 < \(\log N\) < \(N\) < \(N \log N\) < \(N^2\) < \(N^3\) < \(2^N\) < \(N!\)。老师拓展了 P vs NP 问题：多项式时间（如 \(N^{100}\)）与指数级时间（如 \(2^N\)，常见于旅行商等 NP-hard 问题）有质的区别，指数级复杂度随 \(N\) 增长会产生时间爆炸。

    Chapter 3: Lists, Stacks, and Queues (列表、栈与队列)¶

    Abstract Data Type (ADT 抽象数据类型)¶

    • 概念：ADT 等于对象 (Objects) 加上其上的操作 (Operations) 的集合。
    • 深度解释：ADT 是一种超越底层编程语言实现的逻辑结构。比方说实体是猪、牛、马，操作是喂食、拍打，只要遵循这些规则，就是一种抽象数据类型。对于 List，其核心操作就是“增、删、改、查”。

    The List ADT (列表抽象数据类型)¶

    列表的两种核心底层实现方式及其优劣：

    1. 数组实现 (Array Implementation)
      • 在内存中开辟一块连续空间，且必须提前知道/声明容量（Capacity）。
      • 优点：通过下标可以瞬间找到第 \(k\) 个元素，查找时间 \(O(1)\)。
      • 缺点：插入 (Insertion) 和 删除 (Deletion) 极其昂贵。若在中间插入/删除，为了保持连续性，必须将后面的所有数据整体向后/向前移动，最差耗时为 \(O(N)\)。
    2. 链表实现 (Linked Lists)
      • 数据在内存中不需要连续，通过指针（Pointer / Next）将各个分散在堆（Heap）里的节点（Node）串联起来。
      • 优点：插入和删除操作极快，只需断开并重连相邻指针即可，时间 \(O(1)\)。极大地利用了内存碎片（如 malloc 分配）。
      • 缺点：查找极慢，必须顺着头指针顺藤摸瓜，时间 \(O(N)\)。
      • 代码核心陷阱：插入节点 B 到 A 和 C 之间时，必须先让 B 指向 C，再让 A 指向 B。如果顺序反了（A 先指向 B），原来 A 到 C 的指针就会丢失，导致链表断裂。
      • 哨兵节点 (Dummy Head)：在链表前端人为加上一个空节点，它没有实际数据。这样可以统增删逻辑，避免在操作真实头节点时需要写额外的特判语句（如 if (head == NULL)）。
      • 双向链表 (Doubly Linked List)：同时包含前向（left_link）和后向（right_link）指针，可以双向遍历。

    链表的工程应用

    1. 多项式 (Polynomials) 的表示：

      • 如果是密集的多项式，直接用数组（下标当指数，值当系数）最方便。
      • 如果是极度稀疏的多项式（例如包含 \(10x^{1000}\) 但中间全是 0），用数组会浪费海量空间。
      • 用链表完美解决稀疏多项式（用节点同时存储系数、指数及下一个节点的指针）：

    2. 多重链表 (Multilists) 与稀疏矩阵：

      • 例如记录全校 40000 名学生和 2500 门课程的选课关系。如果开二维数组，绝大多数格子都是 0（因为一个人只选几门课）。使用多重链表，只需横向串起学生选的课、纵向串起某门课的所有学生，即可省下海量内存。
    3. 游标实现 (Cursor Implementation - 简述)：
      • 在没有指针的语言中，用数组模拟链表。数组中不再存实际内存地址，而是存放下一个元素在数组里的下标（Index），通过 freelist 机制模拟系统的 malloc 和 free。

    The Stack ADT (栈抽象数据类型)¶

    1. ADT 概念与实现原理

    • 概念：栈是一种具有“先进后出 (FILO) / 后进先出 (LIFO)”特性的数据结构，只能在同一端（栈顶 Top）进行插入 (Push)、删除 (Pop) 和查看操作。
    • 链表实现 (Linked List Implementation)：如果用链表来实现栈，栈顶 (Top) 必须放在链表的头部 (Head)。因为我们所有的操作都在栈顶进行，如果放在尾部，每次寻找或删除都需要遍历整个链表；而放在头部，插入和删除的时间复杂度都是完美的 \(O(1)\)。

    2. 栈的应用 (Applications)

    • Balancing Symbols (符号平衡/括号匹配)：

      • 用于检查代码中的 ()、[]、{} 是否闭合。
      • 代码逻辑：遇到左括号一律入栈；遇到右括号，则去查看栈顶元素。如果栈顶能匹配则双双弹出；如果栈顶不匹配（例如跨级闭合），或者遇到右括号时栈已空，或者最后程序读完但栈内仍有左括号，均判定为不合法。

    • Postfix Evaluation (后缀表达式/逆波兰表达式求值)：

      • 人类习惯用中缀表达式（如 a + b * c），但计算机处理时需要考虑运算优先级，非常麻烦。将中缀转为后缀后（如 6 2 / 3 - 4 2 * +），计算变得极其简单。
      • 计算逻辑：遇到数字就入栈；遇到运算符，就从栈顶弹出两个数字进行运算，并将计算结果重新压回栈中。如此反复，直到最后栈内只剩下一个元素，即为最终结果。

    • Infix to Postfix Conversion (中缀转后缀表达式)：

      • 转换的核心是利用栈来延迟处理优先级较低的运算符。遇到优先级高的先算（输出），遇到优先级低的先入栈等待。
      • 重点规则与代码展示：
        1. 连续减号 a - b - c 转换为 a b - c -；但连续幂运算 2^2^3 必须转换为 2 2 3 ^ ^，因为幂运算的结合性是从右向左 (right to left)。
        2. 括号的处理陷阱：绝对不要把栈内的左括号 ( 弹出来，除非遇到了右括号 )。为了代码实现方便，定义：左括号 ( 在入栈前（栈外）优先级最高（一定能入栈），但一旦进入栈内，优先级降为最低（任何运算符都能压在它上面），直到遇到右括号才将其弹出。

    • Function Calls -- System Stack (函数调用与系统栈)：

      • 调用新函数时，系统会暂停当前函数，将局部变量、返回地址（Return Address）打包成“栈帧 (Stack Frame)”向上压入系统栈。函数执行完毕后，栈帧销毁并出栈，程序跳回返回地址继续执行。因此局部变量不需要手动 free。

      • 深度拓展：C语言底层的安全漏洞

        ：

        1. 为什么会打印出 烫烫烫 或 屯屯屯？如果你的指针越界访问了未初始化的栈空间（系统默认填充特定的十六进制值），就会输出 烫烫烫；如果越界访问了堆空间，就会输出 屯屯屯。
        2. 断错误 (Segmentation Fault)：如果黑客通过数组越界，恶意覆写了系统栈里的返回地址 (Return Address)，函数结束时程序就会跳转到错误的地址或者黑客布置的恶意代码中去，引发断错误或严重的安全漏洞。

    § 4 The Queue ADT (队列抽象数据类型)¶

    • 基本概念：队列是“先进先出 (FIFO)”的结构。在一端插入 (Enqueue)，在另一端删除 (Dequeue)。就像排队买票，先来的先办。

    • 循环数组实现 (Circular Queue)

      ：

      • 队列通常使用数组和 front、rear 两个指针来实现。
      • 为了复用出队后前端空出来的空间，使用取模运算 (Modulo) 形成循环队列：rear = (rear + 1) % Capacity。

    • 工程陷阱：如何区分“队列满”与“队列空”？

      • 在循环队列中，如果数组全满，rear 指针会绕一圈追上 front；如果全空，rear 也会等于 front。仅凭指针重合无法区分满和空。

      • 解决方案

        ：

        1. 少放一个元素：假设容量为 \(N\)，最多只放 \(N-1\) 个元素。牺牲 1 个空间来保证 rear 和 front 永远不会在满的时候重合。
        2. 增加标志位：引入一个额外的变量 size 计数，或者用一个 flag 记录最后一次操作是插入还是删除，以此来判断是空还是满。

    • 链表实现补充：对于不想处理取模和边界问题的情况，直接使用带有头尾双指针的链表是天然且完美的队列实现方式。每次入队向尾部加，出队从头部删，十分便捷。

    CHAPTER 4 Trees (树)¶

    § 1 Preliminaries (基本概念)¶

    • 基础定义 (Definitions)

      ：

      • 树不能存在回路（环），由节点 (Node) 和边 (Edge) 组成。
      • Degree (度数)：一个节点拥有的子树数量。
      • Depth (深度)：从根节点往下数。通常根节点的深度定义为 0（注意看考试提示，部分教材定义为 1）。
      • Height (高度)：从叶子节点往上数，叶子节点高度为 0。

    • List Representation (树的链表表示：左孩子右兄弟)

      ：

      • 普通多叉树的子节点数量不定，直接开辟多个指针会造成极大的内存浪费。
      • 核心转换法：使用 First Child, Next Sibling（左孩子右兄弟）表示法。每个节点固定只保留两个指针：左指针指向它的第一个孩子，右指针指向它的亲兄弟。通过这种方式，可以将任何多叉树或森林完美转换为二叉树结构，顺时针旋转 45 度看即是一棵标准的二叉树。

    § 2 Binary Trees (二叉树)¶

    • 二叉树的核心性质

      ：

      • 深度为 \(K\) 的二叉树，第 \(i\) 层的最大节点数是 \(2^i\)。
      • 重要公式：对于任何非空二叉树，度数为 0 的叶子节点数 \(N_0\) 永远等于度数为 2 的节点数 \(N_2\) 加 1，即 \(N_0 = N_2 + 1\)。这是由于边数推导出来的必然结论（总边数 = 总节点数 - 1）。

    • Abstract Syntax Tree (抽象语法树 AST)

      ：

      • 可以将代码程序转化为树形数学结构（编译器查重和语义分析的基础）。例如 a + b * c / d，叶子节点都是操作数（a, b, c, d），内部节点都是运算符。通过树结构天然保证了运算优先级。

    • 二叉树的遍历 (Tree Traversals)

      ：

      • 深度优先搜索 (DFS)

        ：

        1. 前序遍历 (Preorder)：遇到节点先 visit（访问），再遍历左子树，最后遍历右子树（根-左-右）。
        2. 中序遍历 (Inorder)：先遍历左子树，再 visit 节点，最后遍历右子树（左-根-右）。对抽象语法树进行中序遍历，得到的就是中缀表达式。

        3. 后序遍历 (Postorder)：先左，后右，最后 visit（左-右-根）。对语法树进行后序遍历，得到的就是后缀表达式。

        4. 深度拓展：老师强调，前、中、后序的递归搜索路径和顺序是完全一模一样的（都是一路向左到底，再向右）。它们唯一的区别仅仅在于你选择在什么时候执行 visit（打印输出）这个动作。

      • 广度优先搜索 (BFS)

        ：

        • 层序遍历 (Level-order)：像水波纹一样一层一层往下走。实现方式是借助队列 (Queue)。每出队一个节点，就将其所有孩子按顺序加入队列中。

    • 通过压栈/弹栈序列还原二叉树 (Reconstructing from Push/Pop)

      ：

      • 高频考点：给你一个二叉树遍历时的 Push 和 Pop 序列（通常是中序遍历），让你画出这棵树。

      • 口诀与规则

        ：

        1. Push 代表向下走生成节点，Pop 代表往回退。
        2. 如果一个 Push 前面紧挨着的是 Push，说明这个节点是上一个节点的左孩子。
        3. 如果一个 Push 前面紧挨着的是 Pop，说明这个节点是上一个 Pop 出来节点的右孩子。

    • Threaded Binary Trees (线索二叉树)

      ：

      • 一棵有 \(N\) 个节点的二叉树，一共有 \(2N\) 个指针。实际上只用了 \(N-1\) 个，有 \(N+1\) 个指针是空着的 (Null)，造成了巨大的空间浪费。
      • 线索化：把这些空指针利用起来。如果左指针为空，就让它指向该节点在特定遍历（如中序遍历）下的前驱节点；如果右指针为空，就指向后继节点。这样无需使用系统栈进行递归压栈，只需顺着右侧的线索指针 (Thread) 就能 \(O(1)\) 空间地从头遍历到尾，极大地优化了空间和迭代效率。
