    课程评分规则¶

    • 平时分（封顶 60 分）

      • 作业（10 分）
      • 小测（10 分）
        • 随机课堂测验，无固定时间通知，每次测验 10 分钟，题目选自作业。
        • 注：也可申请免听，免除到课和小测。
      • 期中考试（15 分）
      • lab（25 分 / 30 分）
        • 第一周编程能力测试中，排名前 30% 的学生可选择 hard（满分 30 分），也可选择 normal（满分 25 分），其余学生默认 normal。
        • GTA（助教评分）×50% + GPR（同行评审评分）×50%。
        • 流程：
          1. 提交初始版本用于同行评审（1 周）
          2. 参与同行评审（2 天）
          3. 修改并将最终版本提交给助教（2 天）
          4. 接收助教评分
      • bonus（4 分）

    • 期末考试（40 分）

      • 学生需先获得诚信测试满分，方可参加期末考试。
      • 本学期内若出现任意一次学术不端行为，将直接取消期末考试资格，且课程总成绩记零分，无补救措施。

    Project 要求¶

    1. 封面 / 标题信息

    • 必须包含项目标题（Title of Project）、作者姓名（Author’s Name）和日期（Date: yyyy-mm-dd）。

    • 注意（扣分点）： 日期等基本信息没写会扣分（-1分）。但在第一次提交的互评（Peer Review）版本中，绝对不能出现作者姓名、学号等任何个人信息，否则直接记 0 分。

    2. Chapter 1: Introduction（引言）

    • 需要包含问题描述和算法背景。

    • 注意（扣分点）： 必须用自己的语言描述题目，绝对不能直接照搬照抄原题（抄袭原题会扣 3 分）。

    3. Chapter 2: Algorithm Specification（算法说明）

    • 需要说明解决问题涉及的所有算法和主要的数据结构。

    • 注意（扣分点）： 强烈建议使用伪代码（pseudo-code）+ 自然语言描述，绝对不要直接把项目源代码贴在这里，伪代码应当比源码更容易理解。

    4. Chapter 3: Testing Results（测试结果）

    • 必须提供一个测试用例表（Table of test cases），包含：测试目的、预期结果、程序的实际表现、出现bug的可能原因以及当前状态（pass / corrected / pending）。

    • 注意（扣分点）：

      每一组测试样例都必须写明测试目的（purpose），不写扣 3 分。

      测试数据必须全面：至少要有1组综合测试样例、数据规模上下边界各1组、必须覆盖极限情况（extreme case），再加 n 组随机数据。数据不全通常会扣 4 分。

      建议用图表展示运行时间；

      对于较大的数据，最好在报告中附上生成数据的程序逻辑，以免被质疑数据来源。

    5. Chapter 4: Analysis and Comments（分析与评论）

    • 需要分析算法的时间复杂度和空间复杂度，并写出对未来改进的看法。

    • 注意（扣分点）： 分析复杂度必须写出推导过程，不能直接丢一个结果（无过程会扣 4 分）。

      例如，循环的复杂度应该写：“The loop runs for N times and the complexity of each loop body is O(1), so the total time complexity is O(N).”。

      时间和空间复杂度缺一不可。

    6. Appendix: Source Code (in C)（附录：C语言源码）

    • 最严厉的扣分点： 源码中必须包含至少 30% 以上的注释，否则代码将直接不予评估（可能导致扣 50 分甚至 0 分处理）。

    7. Declaration（独立完成声明）

    • 报告末尾必须附带以下全英文声明： "I hereby declare that all the work done in this project titled "XXX" is of my independent effort."

    文件打包与提交格式要求

    提交的作业必须是一个 .ZIP 压缩包，压缩包内的目录结构有严格要求：

    • documents 文件夹： 存放你的 PDF 报告文件。

    • code 文件夹： 存放 C 语言源码（*.c, *.h）。Readme 文件： 只要代码有两个或以上文件，code 文件夹中就必须包含一个 readme.txt。readme.txt 里面需要写明：如何编译、如何运行、如何输入、期望的输出是什么，最好能提供一组样例输入和输出。

    最终版（提交给助教）的文件命名规则：PDF 报告和源码文件必须按照 Teacher2026_StudentID_ProjectNumber.* 命名。例如你的老师简写是 hqm，学号是 3250103939，做的是 Project 2，则报告命名为 hqm2026_3250103939_P2.pdf
